# eBook Listings - Kindle出版メタデータ一括生成スキル

電子書籍の原稿テキスト → キーワードリサーチ → タイトル・著者名・キーワード7つ・紹介文を一括生成。

## When to Use This Skill

- 「紹介文を作って」「Kindleの紹介文」
- 「タイトル案を出して」「タイトルとキーワードを作って」
- 「電子書籍のメタデータ」「Kindle出版用の情報」
- 「ebook-listings」
- 原稿テキストを渡されて出版情報の作成を求められた場合

## 全体フロー（3フェーズ）

```
Phase 1: 原稿分析
   │  原稿テキストからテーマ・ターゲット・キーコンセプトを抽出
   │  ユーザー指定のキーワードがあれば取得
   │  漫画ページ数・図解数・キャラクター等の差別化要素を収集
   ▼
Phase 2: キーワードリサーチ
   │  WebSearchでAmazon/Kindle市場のキーワード調査
   │  日本語市場＋英語市場の競合分析
   │  差別化ポイントの特定
   │  キーワード候補15-20個 → 最適な7つを選定
   ▼
Phase 3: メタデータ生成
   │  タイトル3案 + 著者名 + キーワード7つ + 紹介文
   │  タイトル・副タイトル・著者名のフリガナ（カタカナ＋ローマ字）
   ▼
完成！ → output/ebook-listings-{slug}/metadata.md に出力
```

## 生成物の仕様

| 項目 | 内容 |
|------|------|
| タイトル・副タイトル | 3案（キーワード密度重視） |
| 著者名 | 「〇〇研究室」形式（キーワード入り） |
| キーワード | 7つ（Kindle登録用） |
| 紹介文 | Kindle商品ページ用（Kindle制約準拠） |
| 出力形式 | Markdown（metadata.md） |

## 出力先

```
output/ebook-listings-{テーマslug}/
└── metadata.md    # タイトル案・著者名・KW7つ・紹介文すべてを含む
```

## Phase 1: 原稿分析

ユーザーから渡された原稿テキストを読み、以下を抽出する：

1. **メインテーマ**: 本の中心的なトピック
2. **ターゲット読者**: 誰に向けた本か（年齢層、職業、悩み）
3. **キーコンセプト**: 本が提供する価値・解決策のコア（一言で表現）
4. **本の特長（数値情報を必ず含める）**:
   - 漫画ページ数（例: 漫画103ページ）
   - 図解・イラスト枚数（例: 図解90枚）
   - 章数・全体ページ数
   - キャラクター（名前・役割・設定）
   - その他差別化要素（付録、特典、音声等）
5. **目次**: 章立て・見出し構成（全章のタイトルとサブセクション）
6. **トーン**: おだやか系 / ガツガツ系 / 技術入門系 / 戦略系
7. **ユーザー指定キーワード**: 原稿内で既に指定されているキーワード
8. **カバーするテーマ一覧**: 章ごとのテーマを列挙（キーワード候補の素材になる）

### 原稿の読み方

- まず `はじめに` と `目次構成` を読んで全体像を把握
- 第1章と活用事例の章を重点的に読む（ターゲットと価値が最もよく表れる）
- 全章を網羅的に読む必要はない。テーマ・ターゲット・差別化要素が特定できれば十分

---

## Phase 2: キーワードリサーチ

### リサーチ手順

1. **シードキーワード抽出**: Phase 1の分析結果からシードキーワードを3-5個抽出
2. **WebSearch実行**（3回、並列実行OK）:
   - 検索1: `{メインテーマ} Kindle 本 Amazon {年}`
   - 検索2: `{メインテーマ} 電子書籍 入門 おすすめ Amazon Kindle {年}`
   - 検索3: `{関連テーマ} Kindle 本 ベストセラー {年}`
3. **競合分析（日本語＋英語の両市場）**:
   - 日本語市場: 同テーマのKindle本のタイトル・著者名・キーワード傾向
   - 英語市場: 海外の同テーマ本のタイトル・切り口の傾向
   - 差別化ポイント: 本書が競合と異なる強みを3つ以上明示
4. **キーワード候補リスト作成**: 15-20個のキーワード候補を生成
5. **最終選定**: 以下の基準で7つに絞り込む

### キーワード選定基準

| 優先度 | 基準 |
|--------|------|
| 最高 | 英語サービス名のカタカナ版（発見率UP） |
| 最高 | サービスの旧名称・別名（名称変遷がある場合） |
| 高 | 検索ボリュームが大きい（一般的な用語） |
| 高 | 本の内容と直接関連する |
| 中 | ロングテール（3語以上の複合キーワード） |
| 中 | 競合が使用しているキーワード |
| 低 | ニッチだが購買意図が高い |

**重要: 汎用的なKW（「AI入門 初心者」「AI 自動化」等）よりも、カタカナ版・旧名称・別名を優先する。**
汎用KWは競合が多く埋もれやすいが、カタカナ版や旧名称は競合が少なく発見率が高い。

### キーワード除外基準

| 除外理由 | 説明 |
|----------|------|
| タイトル・副タイトルに含む | Kindleはタイトルも検索対象。キーワード枠を重複させない |
| 検索ボリュームが極めて小さい | 固有名詞や新造語で検索されにくいもの |
| 本の内容と間接的にしか関連しない | 広すぎる概念（例: 「テクノロジー」） |

### キーワード構成の目安

- メインキーワード: 2-3個（テーマの核心）
- 関連キーワード: 2-3個（周辺トピック・類義語）
- ロングテール/ニッチ: 1-2個（差別化）

### カタカナ・旧名称戦略

英語のキーワードやサービス名がある場合、以下を積極的に候補に含める：

| 種別 | 説明 | 例 |
|------|------|-----|
| カタカナ版 | 英語名をカタカナで検索する人向け | OpenClaw → オープンクロー |
| 旧名称・別名 | 名前が変わったサービスの旧名で検索する人向け | Moltbot, ClawdBot |
| 略称・通称 | 正式名称でなく通称で検索する人向け | Claude Code → クロードコード |

- 英語名のカタカナ版はタイトルに含まれていてもキーワードに入れてOK（検索補完として有効）
- サービスの歴史的な名称変遷がある場合、旧名称をキーワードに含めると発見率が上がる

## Phase 3: メタデータ生成

### 3-1. タイトル・副タイトル（3案）

各提案は以下の構造で作成する：

```
【提案N：コンセプトの一言説明】
タイトル
{キーワードを含む、30文字以内のインパクトあるタイトル}

副タイトル
{キーワードを含む、本の価値と読者ベネフィットを伝える副タイトル}
```

**タイトル作成ルール:**
- 必ず1つ以上のメインキーワードを含める
- 30文字以内を目安（長すぎると検索で切れる）
- **英語のサービス名・ツール名にはカタカナ読みを（）で付記する**
  - 例: `OpenClaw（オープンクロー）`、`Claude Code（クロードコード）`
  - カタカナで検索する人にもヒットするようにする
- **複数テーマがある場合は `×` で接続する**
  - 例: `OpenClaw（オープンクロー）×Claude Code（クロードコード）`
- ターゲット読者を冒頭に明示するとクリック率が上がる
  - 例: `非エンジニア向けの`、`初心者のための`
- 数字を入れると具体性が増す

**副タイトル作成ルール:**
- **キーワードを `×` で接続して並べ、その後にベネフィット文を続ける**
  - 例: `AIエージェント×AI秘書×Claude Code パソコンが苦手でも話題の3大テーマを完全理解`
- テーマ数を数字で集約すると訴求力が上がる（「3大テーマ」「5つの秘訣」等）
- 読者が「自分のための本だ」と感じるベネフィットを記述
- 漫画ページ数・図解数などの数値スペックがあれば積極的に入れる

**3案の方向性:**
- 提案1: 網羅性・キーワード密度重視
- 提案2: 好奇心・秘匿性で引きつける
- 提案3: 簡単さ・具体的成果を打ち出す

### 3-2. 著者名

```
{メインKW}（{テーマ1}×{テーマ2}）活用研究室
```

**作成ルール:**
- Amazon検索でヒットするキーワードを含める
- **括弧内にもテーマキーワードを `×` で接続して入れる**（キーワード密度を最大化）
  - 例: `AIエージェント（OpenClaw×Claude Code）活用研究室`
  - 例: `AI副業（ChatGPT×note）収益化研究室`
- 「研究室」「ラボ」「アカデミー」等の信頼感のある語尾
- 「活用」「実践」「収益化」等の修飾語でジャンルを明示

### 3-3. キーワード7つ

Phase 2で選定した7つのキーワードをリスト形式で出力。

```
keyword  {キーワード1} {キーワード2} {キーワード3} {キーワード4} {キーワード5} {キーワード6} {キーワード7}
```

### 3-4. フリガナ（カタカナ・ローマ字）

タイトル・副タイトル・著者名のそれぞれについて、Kindle登録用のカタカナ表記とローマ字表記を生成する。

**変換ルール（絶対遵守）:**

```
1. ひらがな → カタカナに変換
2. `×` → 「カケル」/ kakeru に変換（スペースではなく読みにする）
3. 。や記号（！、（）等）→ 半角スペースに置き換え
4. それ以外の文字 → 半角スペースを空けない（詰める）
5. 漢字 → 読みをカタカナ/ローマ字で記述
6. 英語 → カタカナ読み / ローマ字読みで記述
7. 長音 → カタカナは「ー」、ローマ字は母音を伸ばす（例: コード→koodo）
```

**出力形式（タイトル・副タイトル・著者名の各項目で）:**

```
### {項目名} フリガナ

カタカナ
{カタカナ変換結果}

ローマ字
{ローマ字変換結果}
```

**変換例:**

| 原文 | カタカナ | ローマ字 |
|------|---------|---------|
| 非エンジニア向けの | ヒエンジニアムケノ | hienjiniamukenno |
| OpenClaw（オープンクロー） | オープンクロー オープンクロー | oopunkuroo oopunkuroo |
| Claude Code（クロードコード） | クロードコード クロードコード | kuroodokoodo kuroodokoodo |
| AI秘書 | エーアイヒショ | eeaihisho |
| 活用研究室 | カツヨウケンキュウシツ | katsuyoukenkyuushitsu |

### 3-5. 紹介文（Kindle商品ページ用）

#### Kindle紹介文の制約（絶対遵守）

- emoji禁止（絵文字は使わない）
- 区切り線禁止（---、━━━、■■■等は使わない）
- 装飾記号禁止（★☆●○△▲等は使わない）
- HTMLタグ禁止
- 目次はキーワードSEO対策として必ず含める
- プレーンテキストのみ（太字・斜体もなし）
- 使用OK: `・`（中黒）、`--`（ダッシュ代替）、`「」`（かぎ括弧）、数字、括弧

#### 紹介文の構成テンプレート

原稿のトーンに合わせて以下4タイプから最適なものを自動選択する。

#### タイプ自動選択の基準

| 原稿の特徴 | 選択タイプ |
|------------|-----------|
| 初心者向け、生活改善、やさしいトーン | タイプA: おだやか共感型 |
| 副業、収益化、稼ぐ、金額目標あり | タイプB: 成果アピール型 |
| BtoB、マーケティング、広告、戦略 | タイプC: BtoB戦略型 |
| IT技術、図解、マンガ付き、ツール解説 | タイプD: 技術入門型 |

複数の特徴が該当する場合は、最も強い特徴に合わせて選択する。

## 使い方

```
# 基本的な使い方
原稿テキストを貼り付けて「紹介文を作って」「Kindleのメタデータを作って」と依頼

# 既にキーワードが決まっている場合
原稿テキスト + 「keyword: {KW1} {KW2} ...」を一緒に渡す
→ ユーザー指定キーワードを優先的に採用

# タイトルだけ再生成したい場合
「タイトルだけ別案を出して」→ Phase 3のタイトル部分のみ再実行

# 紹介文のタイプを指定したい場合
「タイプBで紹介文を作って」→ 指定タイプで生成
```

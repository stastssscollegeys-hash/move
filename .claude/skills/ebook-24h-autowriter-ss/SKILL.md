# eBook 24H AutoWriter - 電子書籍テキスト＋Word＋出版情報＋表紙 一括生成スキル

参考資料 → リサーチ → 原稿（25,000字）→ 高品質DOCX → 出版メタデータ → 表紙プロンプト → 表紙JPEG を一括生成。
画像生成を省き、テキストとWord整形に特化した量産向けスキル。OpenRouterからも利用可。
**全フロー確認なしで自動進行する。**

## When to Use This Skill

- 「テキストのみで電子書籍作って」「テキストのみ」
- 「24Hオートライターで」「24時間ライターで書いて」
- 「画像なしで本を作りたい」「テキストだけの電子書籍」
- OpenRouterから使われることが多い
- 「電子書籍リサーチして書いて」→ まず `kindle-theme-research-ss` でリサーチ → 本スキルで執筆

## Do NOT Use for

- 図解画像入りの電子書籍 → `ebook-creator-ss` を使用
- 漫画の書籍 → `ebook-creator-ss` → `manga-produce-kobetsu-ss` を使用
- ゼロから漫画 → `manga-creator-ss` を使用

## Phase 2: 深層リサーチ

### 手順

1. 参考資料からテーマ・キーワードを抽出する
2. 以下の5層リサーチを**サブエージェント並列で**実行する
3. リサーチ結果を `output/{slug}/research.md` に保存する
4. **確認なし**でPhase 3へ進む

### サブエージェント分割（推奨）

```
Agent 1: Layer 1（YouTube） + Layer 2（note）
Agent 2: Layer 3（SNS/ショート動画） + Layer 5（読者の悩み）
Agent 3: Layer 4（市場・競合・書籍分析）
```

### 5層リサーチ（すべて実行すること）

#### Layer 1: YouTube 専門家の知見

テーマに関する専門チャンネルの動画を調査し、ノウハウを抽出する。

```
手順:
1. WebSearch で「{テーマ} site:youtube.com」を検索
2. 再生回数が多い動画・専門チャンネルを特定（5〜10本）
3. 各動画について:
   a. WebFetch で動画ページを取得し、タイトル・概要欄・チャンネル情報を確認
   b. 動画の要点・独自のノウハウ・具体的手法を抽出
4. 専門家ごとに主張や手法の違いを整理する
```

検索キーワード例:
- `{テーマ} やり方 解説`
- `{テーマ} 初心者 完全ガイド`
- `{テーマ} プロ 実践`
- `{テーマ} 2025 2026 最新`

#### Layer 2: note 専門家の記事

note.com で専門的に発信している人の記事を深掘りする。

```
手順:
1. WebSearch で「{テーマ} site:note.com」を検索
2. 上位記事を5〜10本特定
3. WebFetch で各記事の内容を取得
4. 以下を抽出:
   - 著者の専門性・実績
   - 独自のフレームワーク・メソッド
   - 具体的な数値・事例
   - 読者からの反応（コメント・スキ数で人気度を判断）
5. 有料記事は概要・目次部分から構成の参考にする
```

#### Layer 3: Instagram / TikTok / ショート動画トレンド

最新トレンドとバズっている切り口を調査する。

```
手順:
1. WebSearch で以下を検索:
   - 「{テーマ} Instagram リール 人気」
   - 「{テーマ} TikTok バズ」
   - 「{テーマ} ショート動画 トレンド」
   - 「{テーマ} SNS 話題」
2. トレンド系まとめサイト・ニュースを WebFetch で取得
3. 以下を抽出:
   - 今バズっているキーワード・ハッシュタグ
   - ショート動画で多い切り口・フォーマット
   - インフルエンサーが推しているポイント
   - Z世代・若年層に響いている表現や訴求
```

#### Layer 4: 市場・競合・書籍分析

既存の書籍・コンテンツとの差別化ポイントを調査する。

```
手順:
1. WebSearch で「{テーマ} 本 おすすめ」「{テーマ} Kindle」を検索
2. Amazon の書籍ページを WebFetch で取得（上位5冊）
3. 以下を抽出:
   - 各書籍の目次構成・切り口
   - 読者レビューで「良かった点」「足りない点」
   - 星1-2のレビューから読者の不満・期待
4. 競合にない切り口、カバーされていない領域を特定
```

#### Layer 5: 読者の悩み・ニーズ

ターゲット読者のリアルな声を収集する。

```
手順:
1. WebSearch で以下を検索:
   - 「{テーマ} 悩み」「{テーマ} わからない」
   - 「{テーマ} site:detail.chiebukuro.yahoo.co.jp」（Yahoo知恵袋）
   - 「{テーマ} site:reddit.com」（海外の議論）
2. WebFetch で上位のQ&Aページを取得
3. 以下を抽出:
   - よくある質問・つまづきポイント
   - 初心者が最初にぶつかる壁
   - 「こういう本があれば」という要望
   - 解決策として支持されている回答
```

## Phase 3: 構成設計

### 手順

1. 参考資料（Phase 1）とリサーチ結果（Phase 2）を元に目次を生成する
2. **確認なし**で自動的にPhase 4へ進む

### 目次生成テンプレート

以下の形式で目次を生成し、そのまま採用する：

```
書籍タイトル: {テーマから最適なタイトルを自動生成}
想定読者: {テーマから推定}
読者のゴール: {この本を読んで何ができるようになるか}

---

はじめに（1,200〜1,500字）
  - この本の目的
  - 読者への約束
  - 本書の使い方

第1章: {章タイトル}（4,000〜5,000字）
  1.1 {節タイトル}
  1.2 {節タイトル}
  1.3 {節タイトル}
  1.4 {節タイトル}
  1.5 {節タイトル}

第2章〜第5章: （同上の形式、各5節）

### 構成設計のルール

- 章の順序は「基礎 → 応用 → 実践」の流れにする
- 各章は独立して読んでも価値があるようにする
- 章をまたいで内容が行ったり来たりしないようにする
- 読者が「次に何をすればいいか」がわかる構成にする

## Phase 4: 原稿執筆（テキストのみ）

### 手順

1. Phase 3で生成した目次 + 参考資料 + リサーチ結果に基づいて全原稿を執筆する
2. **サブエージェント並列**で効率的に執筆する
3. 完成した原稿を `output/{slug}/manuscript.md` に保存する
4. **確認なし**でPhase 5へ進む

### サブエージェント分割（推奨）

```
Agent 1: はじめに + 第1章 + 第2章
Agent 2: 第3章 + 第4章
Agent 3: 第5章 + おわりに
```

各エージェントに渡す情報:
- 目次（全体構成がわかるように）
- 参考資料の該当部分
- リサーチ結果の該当部分
- 執筆ルール（下記）
- 他のエージェントの担当範囲（内容の重複を防ぐため）

### 執筆ルール

- **総文字数**: 約25,000字（はじめに + 5章 + おわりに）
- **1章あたり**: 4,000〜5,000字
- **はじめに/おわりに**: 各1,200〜1,500字
- **文字数の厳守**: AIは文字数を過少に生成しがち。各章の執筆後に文字数をカウントし、4,000字に満たない章は加筆すること
- **文体**: **です・ます調で統一**（「〜です」「〜ます」「〜ください」）。親しみやすく丁寧な語り口
  - NG: 「〜だ」「〜である」「〜しよう」
  - OK: 「〜です」「〜になります」「〜してみましょう」「〜してください」
- **段落**: 3〜4文ごとに改行。読みやすさ重視
- **具体例**: 各章に最低2つの具体例・事例を含める
- **画像なし**: 画像タグ（`<!-- [INLINE_IMAGE] -->` 等）は一切使用しない。テキストのみで完結させる
- **表（テーブル）の使用禁止**: Markdownの表記法（`| ... |`形式）は**使用禁止**。Word出力時にレイアウトが崩れやすい。比較・一覧情報は箇条書きで表現する
- **箇条書き**: 通常のMarkdownリスト記法（`-`, `1.`）を使用してOK
- **ASCII図・記号図の禁止**: 罫線文字（`┌─┐│└─┘`等）や記号を組み合わせて図を表現しないこと
- **コードブロック（` ``` `）の禁止**: コマンド等は通常テキストとしてそのまま記述する
- **ユーザー名の禁止**: 原稿中にユーザー個人の名前を入れない。「読者の皆さん」等の一般的な表現を使う
- **著者情報の禁止**: 原稿本文に著者名・著者プロフィール・著者紹介・自己紹介を一切入れない。著者情報はKindle出版時にユーザーが自分で設定するため、本文中では不要。「おわりに」でも著者の経歴や肩書きには触れない

### 改ページ・整形ルール（DOCX出力品質に直結）

#### 改ページ（`\newpage`）の挿入位置

1. **各章（`##`）の直前**: `## 第N章` の前に必ず `\newpage`
2. **各節（`###`）の直前**: `### N.M` の前に必ず `\newpage`
3. **はじめに・おわりにの直前**: `## はじめに` `## おわりに` の前にも `\newpage`

#### 空行ルール

1. **見出し（`##` `###`）の前**: 改ページ（`\newpage`）+ 空行1行 + 見出し
2. **見出しの後**: 見出し + 空行1行 + 本文開始
3. **段落間**: 段落と段落の間に空行1行（Markdownの通常ルール）
4. **箇条書きの前後**: 箇条書きブロックの前後に空行1行ずつ

#### 見出しレベルの使い分け

- `#` 見出し1: 書籍タイトル（冒頭1回のみ）
- `##` 見出し2: 章タイトル（はじめに、第1章〜第5章、おわりに）
- `###` 見出し3: 節タイトル（1.1, 1.2, ...）
- `####` 見出し4: 小見出し（必要に応じて）

## Phase 5: DOCX変換 + 後処理

### 概要

Pandocで高品質DOCX変換した後、3つの後処理を行い読みやすいWordファイルを生成する。

### DOCX整形3大ルール（絶対遵守）

```
┌─────────────────────────────────────────────────────────────────────┐
│  ルール1: 目次（TOC）を入れない                                     │
│  ルール2: 段落間にスペース（空行）を入れる（詰まりすぎ防止）        │
│  ルール3: 見出し・章の前に改ページを入れる                           │
└─────────────────────────────────────────────────────────────────────┘
```

### 手順

1. `manuscript.md` の整形チェック（下記チェックリスト）
2. 不備があれば自動修正する
3. Pandocで変換（**--tocオプションは使わない**）
4. python-docxで後処理を実行:
   a. 「。」→「。+段落区切り」（句点改行）
   b. 段落間スペースの追加（段落後に適切なスペース）
   c. 見出し・章の前に改ページ挿入
5. **確認なし**でPhase 6へ進む

### 変換前チェックリスト（自動チェック・自動修正）

```
□ 各章（## 第N章）の直前に \newpage がある
□ 各節（### N.M）の直前に \newpage がある
□ はじめに・おわりにの直前に \newpage がある
□ 見出しの前後に空行がある
□ 段落間に空行がある
□ 箇条書きの前後に空行がある
□ テーブル記法（| ... |）が使われていない
□ コードブロック（```）が使われていない
□ ASCII図（罫線文字）が使われていない
□ 画像タグ（<!-- [IMAGE] -->）が混入していない
```

不備があればEditツールで自動修正してから変換する。

### DOCX後処理スクリプト（3大ルール適用）

Pandoc変換後に以下の3つの処理を一括実行する:

1. **見出し・章前の改ページ**: Heading 1/2/3 の前に改ページを挿入
2. **句点改行**: 「。」で文を分割し、各文を独立段落にする
3. **段落間の空行挿入**: 元のMarkdown段落の区切りに**実際の空段落要素**を挿入して視覚的に段落グループを分離する
4. **画像前後の空行挿入**: 画像（drawing要素）を含む段落の前後に空行を挿入して、画像と本文を視覚的に分離する

> **重要**: `w:spacing`（段落後スペース）ではなく、**実際の空の`w:p`要素**を挿入すること。
> `w:spacing` プロパティはDOCX上で視覚的な段落間スペースとして反映されないため、
> 必ず `OxmlElement('w:p')` で空段落を挿入する方式を使う。これは検証済みの確定仕様。

```bash
cd "/c/Users/baseb/dev/開発1/output/{slug}"

python -c "
from docx import Document
from docx.oxml.ns import qn
from docx.oxml import OxmlElement
from copy import deepcopy

doc = Document('manuscript.docx')

# === 処理1: 見出し・章前の改ページ ===
heading_styles = {'Heading 1', 'Heading 2', 'Heading 3'}
for para in doc.paragraphs:
    style_name = para.style.name if para.style else ''
    if style_name in heading_styles:
        pPr = para._element.get_or_add_pPr()
        existing = pPr.find(qn('w:pageBreakBefore'))
        if existing is None:
            pb = OxmlElement('w:pageBreakBefore')
            pPr.append(pb)

# === 処理2: 句点改行 + 段落の切れ目に空行挿入 + 画像前後に空行 ===
paras = list(doc.paragraphs)
for para in paras:
    style_name = para.style.name if para.style else ''
    text = para.text.strip()

    # 見出しはスキップ
    if style_name.startswith('Heading'):
        continue

    # 画像段落の検出（drawing要素を含む段落）
    has_drawing = bool(
        para._element.findall('.//{http://schemas.openxmlformats.org/drawingml/2006/wordprocessingDrawing}inline') or
        para._element.findall('.//{http://schemas.openxmlformats.org/drawingml/2006/wordprocessingDrawing}anchor')
    )

    if has_drawing:
        # 画像段落 → 前後に空行を挿入
        p_element = para._element
        parent = p_element.getparent()
        idx = list(parent).index(p_element)
        # 前に空行（前の要素が空段落でなければ）
        if idx > 0:
            prev = parent[idx - 1]
            prev_runs = prev.findall(qn('w:r'))
            prev_is_empty = (len(prev_runs) == 0 and not any(child.tag.endswith('}drawing') for child in prev.iter()))
            if not prev_is_empty:
                empty_before = OxmlElement('w:p')
                parent.insert(idx, empty_before)
                idx += 1
        # 後に空行
        empty_after = OxmlElement('w:p')
        parent.insert(idx + 1, empty_after)
        continue

    # 空テキスト段落（画像でもない）はスキップ
    if not text:
        continue

    # 画像キャプションはスキップ（空行不要）
    if style_name == 'Image Caption':
        continue

    if '。' not in text:
        # 句点なし段落 → その後に空行を挿入（段落区切り）
        p_element = para._element
        parent = p_element.getparent()
        idx = list(parent).index(p_element)
        empty_p = OxmlElement('w:p')
        parent.insert(idx + 1, empty_p)
        continue

    sentences = [s for s in text.split('。') if s.strip()]
    if len(sentences) <= 1:
        # 1文段落 → その後に空行を挿入（段落区切り）
        p_element = para._element
        parent = p_element.getparent()
        idx = list(parent).index(p_element)
        empty_p = OxmlElement('w:p')
        parent.insert(idx + 1, empty_p)
        continue

    p_element = para._element
    parent = p_element.getparent()
    idx = list(parent).index(p_element)
    new_elements = []

    for i, sentence in enumerate(sentences):
        st = sentence.strip()
        if not st:
            continue
        if i < len(sentences) - 1 or text.rstrip().endswith('。'):
            st += '。'

        new_p = deepcopy(p_element)
        for r in new_p.findall(qn('w:r')):
            new_p.remove(r)
        new_r = OxmlElement('w:r')
        if para.runs:
            rPr = para.runs[0]._element.find(qn('w:rPr'))
            if rPr is not None:
                new_r.append(deepcopy(rPr))
        new_t = OxmlElement('w:t')
        new_t.set(qn('xml:space'), 'preserve')
        new_t.text = st
        new_r.append(new_t)
        new_p.append(new_r)
        new_elements.append(new_p)

    # 最後に空行（元の段落の区切り）を追加
    empty_p = OxmlElement('w:p')
    new_elements.append(empty_p)

    for j, new_el in enumerate(new_elements):
        parent.insert(idx + j, new_el)
    parent.remove(p_element)

doc.save('manuscript.docx')
print('DOCX後処理完了（改ページ + 句点改行 + 空行挿入 + 画像前後空行）')
"
```

**注意**: python-docxがインストールされていない場合は `pip install python-docx` を実行する。
python-docxが使えない環境では、ユーザーにWord上での手動手順を案内する:

```
手動手順（Word上で実行）:
1. 句点改行: [Ctrl]+[H] → 検索「。」→ 置換「。^p」→ すべて置換
2. 段落間空行: [Ctrl]+[H] → 検索「^p^p」がない段落グループの末尾に手動で空行を追加
3. 改ページ: 各見出しを選択 → 段落設定 → 「改ページ」タブ → 「段落前で改ページする」にチェック
```

## Phase 6: 出版メタデータ生成（ebook-listings-ssロジック）

### 概要

完成原稿を分析し、Kindle出版用メタデータを生成して `listing.txt` に出力する。

### 手順

1. `manuscript.md` からテーマ・ターゲット・キーコンセプト・目次を抽出
2. WebSearchでキーワードリサーチ（サブエージェント推奨）
3. メタデータを生成して `listing.txt` に出力
4. **確認なし**でPhase 7へ進む

### Phase 6-1: 原稿分析

原稿から以下を抽出する:

- メインテーマ
- ターゲット読者
- キーコンセプト（一言で表現）
- 本の特長（章数・ボリューム等の数値情報）
- 目次構成
- トーン判定（おだやか系 / ガツガツ系 / 技術入門系 / 戦略系）

### Phase 6-2: キーワードリサーチ

サブエージェントで以下を実行:

```
検索1: {メインテーマ} Kindle 本 Amazon {年}
検索2: {メインテーマ} 電子書籍 入門 おすすめ Amazon Kindle {年}
検索3: {関連テーマ} Kindle 本 ベストセラー {年}
```

- 日本語市場 + 英語市場の競合分析
- 差別化ポイント3つ以上
- キーワード候補15-20個 → 最適な7つを選定

キーワード選定基準:
- タイトル・副タイトルに含まれるKWは除外（Kindleはタイトルも検索対象）
- メインKW 2-3個、関連KW 2-3個、ロングテール 1-2個
- カタカナ版・旧名称・類義語を優先

### Phase 6-3: メタデータ生成

#### タイトル・副タイトル（3案）

```
【提案N：コンセプト】
タイトル: {30文字以内、メインキーワードを必ず含む}
副タイトル: {関連キーワードを×で接続 + ベネフィット文}
```

> **最重要ルール**: 企画の中心となるメインキーワード（例: 認知バイアス、ChatGPT、副業 等）は**必ずタイトル（メインタイトル）に入れる**。副タイトルだけに入れるのは禁止。メインキーワードはAmazon検索で最も重要な語であり、タイトルに含まれることで検索ヒット率が大幅に上がる。

3案の方向性:
- 提案1: 網羅性・キーワード密度重視
- 提案2: 好奇心・秘匿性で引きつける
- 提案3: 簡単さ・具体的成果を打ち出す

#### 著者名

```
{メインKW}（{テーマ1}×{テーマ2}）活用研究室
```

#### キーワード7つ

```
keyword {KW1} {KW2} {KW3} {KW4} {KW5} {KW6} {KW7}
```

#### フリガナ（カタカナ・ローマ字）

タイトル・副タイトル・著者名のそれぞれについて生成。

変換ルール:
- ひらがな → カタカナ
- `×` → 「カケル」/ kakeru
- 記号 → 半角スペース
- 漢字 → 読みをカタカナ/ローマ字
- 英語 → カタカナ読み/ローマ字読み
- 数字 → 読みをカタカナ/ローマ字（フリガナに数字は使えない）

#### 紹介文（Kindle商品ページ用）

Kindle紹介文の制約:
- emoji禁止、区切り線禁止、装飾記号禁止、HTMLタグ禁止
- プレーンテキストのみ
- 使用OK: `・`（中黒）、`--`、`「」`、数字、括弧
- 目次はキーワードSEO対策として必ず含める

原稿のトーンに合わせて4タイプから自動選択:

| 原稿の特徴 | 選択タイプ |
|------------|-----------|
| 初心者向け、生活改善、やさしいトーン | タイプA: おだやか共感型 |
| 副業、収益化、稼ぐ、金額目標あり | タイプB: 成果アピール型 |
| BtoB、マーケティング、広告、戦略 | タイプC: BtoB戦略型 |
| IT技術、図解、ツール解説 | タイプD: 技術入門型 |

## Phase 7: 表紙プロンプト生成（cover-master-ss形式）

### 概要

完成原稿を分析し、cover-master-ss形式のYAMLプロンプト（Version A + B）を生成して `cover_prompt.txt` に出力する。

### 手順

1. `manuscript.md` からジャンル・テーマ・キーワードを自動抽出
2. スタイルを自動選択（A〜E）
3. カラーパレットを自動選択
4. YAMLプロンプト（Version A + B）を生成
5. `cover_prompt.txt` に出力（戦略コンセプト + YAML + 後工程ガイド）
6. **確認なし**でPhase 8へ進む

### スタイル自動選択

```
ビジネス/自己啓発/話し方/時間術 → A（テキストインパクト型）
料理/健康/ダイエット/生活改善/趣味 → B（イラスト＋テキスト型）
マンガ解説/AI活用/テック入門/ラノベ → C（マンガ・アニメ型）
投資/金融/経営戦略/不動産 → D（ダーク・プレミアム型）
副業/ChatGPT×副業/〇〇入門/ハウツー → E（ハイブリッド型）
心理学/行動経済学 → A or D（内容の重厚さで判断）
```

### カラーパレット自動選択

| ジャンル | メイン | アクセント | ハイライト |
|---------|--------|----------|-----------|
| ビジネス | #FFFFFF 白 | #1A1A2E 紺 | #E74C3C 赤 |
| 自己啓発 | #FFF3CD 薄黄 | #E74C3C 赤 | #FFD700 金 |
| 投資・マネー | #1B2A4A 紺 | #D4AF37 金 | #FFFFFF 白 |
| 健康・ダイエット | #E8F5E9 薄緑 | #FF6B6B ピンク | #2E7D32 緑 |
| AI・テック | #1A73E8 青 | #FFD700 金 | #FF5252 赤 |
| 副業・稼ぐ系 | #FFF9C4 黄 | #1565C0 紺 | #FF5722 オレンジ |
| 心理学 | #0D1B2A ダークネイビー | #E8872A オレンジ | #D4AF37 ゴールド |

### YAMLプロンプト生成

cover-master-ss/SKILL.md の **Version A テンプレート（文字入り）のみ**を使用して生成する。Version B（文字なし素材用）は生成しない。

### cover_prompt.txt の出力形式

```
━━━ 表紙プロンプト生成結果 ━━━

■ 選択スタイル: [X] - [名称]
■ カラーパレット: [メイン] / [アクセント] / [ハイライト]
■ キャラクター: [あり/なし]
■ 参照画像: [あり/なし]
■ コンテンツ量: 全[N]章 / [N]字

━━━ Version A（文字入り） ━━━
{YAMLプロンプト全文}
```

YAMLプロンプトの設計原則:
- フラット構造: text_elements に全テキストを集約
- 簡潔記述: 1要素 = 2-3行
- 自然言語: Geminiは自然な文章の方が理解しやすい
- constraint最小: 本当に重要な4-5個だけ
- Zパターン: 視線誘導を明示
- 色はHEX値+色名: `#1A73E8 blue` のように両方記載
- portrait 2:3: Kindle縦長比率を明示
- **著者名は絶対に入れない**: text_elementsに著者名フィールドを含めない。constraintsに `"DO NOT include any author name, writer name, or 著者 text anywhere on the cover"` を必ず含める。著者名はKindle出版時にユーザーが自分で設定する

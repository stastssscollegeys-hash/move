## 0. 目的と、今わかっていること

**目的（ユーザー指定・最上位）: 的中率ではなく、年間を通した回収率100%超。当面の目標は120%。**
評価も判定も回収率（前向き台帳の累計と95%区間）で行う。的中率は判定に使わない。

| 事実（10年・年ごとの前向き検証） | 数字 |

| 確率エンジン（市場＋調教・過去走・傾向）は市場より少し正確 | 対数尤度 +0.00657/レース（8年中7年改善） |

## 0b. 予想の根本の考え方（ユーザー提示・2026-11-01・**今後の予想はこの順で組み立てる**）
正本は docs/keiba_user_thinking_framework.md（口述の全文と、エンジンとの対応・検証候補）。

1. **まず「買えるレース・買える馬券か」**（期待値が最優先。回収率で語る）。勝負レース（期待値の取れるレース）だけ投稿・台帳。旨味が薄ければ点数を絞って少額、見送りもある。
2. **馬の実力を数値にする**: タイム／ラップ（時計の指数・馬場差補正）、ペース・位置取り、戦ってきた相手（相手関係）、他馬との横比較、ペース・コース・トラックバイアスへの適性。→ `ev_engine.py` の特徴量。**無い要素（相手関係・馬ごとのラップ型・馬ごとのバイアス適性・厩舎コメント・新聞印・追い切りの乗り手）は検証候補**（docs §1・§3）。
3. **レース・コースの特徴を重ねる**（過去10年の傾向）: 勝ちやすい馬・位置取り・馬場・ペースの出方・血統。→ `course_profile.py`／`race_profile.py`／`race_history.py`、特徴量35〜52。
4. **最新情報を入れる**: 当日のトラックバイアス（内外・前後・フラット）、前日のペース・時計、馬体重、追い切り（時計・乗り手・全体順位）、厩舎コメント、世間の評価（新聞・SNS。参考表示）。バイアスやペースは**説明と判断材料**（確率に入れる検証は不採用＝§4）。
5. **過小評価を拾い、過大評価を軽視する**: 「負けたが不利・展開・バイアスで負けただけの実力馬」を人気薄のうちに拾う、恵まれて好走しただけの人気馬を軽視する＝割安さ（モデル÷市場）の印そのもの。ただし**前走の逆風だけでは拾えない**（単勝71%・市場が織り込み済み）ことは検証済み（§4）。
6. **買い目は固定しない**: レースの期待値と印の重さで型・金額・点数を変える（`kaime_compose`）。**軸は本命と決めない**: 上位印の○・▲に6番人気以下で割安な馬がいれば、そこから◎へ流す（K13）。**外れ用の保険**（◎が飛ぶなら○▲、穴軸が飛ぶなら◎と人気側、大穴🔥の激走）も入れる。印の馬は必ず買い目に入れる（印と買い目の一致）。
7. **判定は前向き台帳**（E2.1・U1・B1）。1日・1レースで何も決めない。新しい要素は事前登録→前向きで測る→2回再現で昇格。

## 2. 守ること（禁止・必須）

### 分析
- 🔴 新しい要素は**年ごとの前向き検証**（`ev_engine.py --walk`）か**新しいレース**（`fresh_test.py`）で改善を確かめてから入れる。在サンプルの発見はそのまま使わない
- 🔴 週末1場の偏り（枠・脚質）を一般則にしない。10年で人気を条件にして再現を確かめる
- 🔴 蓄積DBの「脚質」はそのレースの結果（コーナー通過）。予想に使うのは**直近5走から作った想定脚質**だけ
- 🔴（2026-11-01）`race_results.json` の **AI印・独自指数・本命的中・F01〜F17 は結果を使った事後スコア（結果リーク）**。集計すると◎勝率71.5%・単勝回収424%と出るが事前予想の成績ではない。事前予想の成績は `cards_versions` の発走前の版（`postmortem_all.py`）と前向き台帳だけで測る
- 🔴 レース前にペースは当てられない（44%＜常にM 46%）。展開は「前に行きたい馬の数」までにとどめる
- 🔴 オッズの急落を買う根拠にしない（発走5分前までの売れ方で選ぶと回収73〜78%。効く情報は最後の数分にしか出ない）
- 🔴 補正の幅が足りないと思ったら、幅を広げる前に要素そのものを疑う
- 壊れた式は、成績が変わらなくても直す（旧版を退避し、切り替わり目を記録）
- 🔴（2026-10-19）元データの「脚質」の「逃げ」は**最初のコーナー2番手以内**（1番手だけではない）。レースやコースの脚質の表は `course_profile.style_of`（通過順から付け直し）で作る。`race_profile.py` はこれに直した（旧版は菊花賞を「差し26%＞先行10%」と逆に出していた。正しくは 先行24%＞差し18%・勝ち馬の7頭が先行）。カードの文章は「最初のコーナーで2番手以内」と書く。エンジンの特徴量と印の「後ろから型」は元の定義のまま前向き検証済み＝変えない
- 🔴（2026-10-19）**配当は確定オッズで払われる（パリミュチュエル）**。作った時点の市場に勝っても（10/17 は対数尤度+0.03）確定オッズの市場とは同水準だった＝上乗せは発走までにオッズへ織り込まれる。評価は確定オッズの市場・台帳（発走35分前の登録）で
- 条件別の当たり具合は `calib_audit.py`（前向き確率で 間隔・前走・距離変化・人気など区分ごとの A/E をモデルと市場で比較 → `docs/keiba_calib_audit.md`）。2026-10-19 時点で「モデルだけが外れている区分」はゼロ＝条件別の補正で伸ばす余地は小さい。長休み明けの重賞好走馬はモデルも市場も勝つ確率を高く見すぎ（A/E 0.84）＝「実績馬の休み明けを上げる」補正は入れない

- 🔴 `predict_day.py` を終わった日に回さない（予想できるレースが無いと止まるようにした。10/04の最終版は一度消えた）
- 🔴 JRA-VAN のデータそのもの（生ファイル・変換したJSON）は Git に入れない（再配布不可）。Git はプログラムだけ

### 馬券・金額
- 🔴 **100円単位**。予算は**基本1万円前後で、旨味（買い目全体の期待回収率）に応じて増減**（2026-10-31 ユーザー指示「1万円きっかりの制限はない。旨味がなければ点数を絞って少額でよい。期待値が取れても上限は15,000円」）。実装は `kaime_compose.budget_for`・`compose`（定数 `BUDGET`=10,000／`BUDGET_MAX`=15,000）
  - 期待回収率 e ≧1.10→15,000円 ／ 1.00〜1.10→12,000円 ／ 0.70〜1.00→1万円前後（紐を足した分は少し超えてよい・上限15,000円） ／ 0.55〜0.70→6,000円（期待値0.5未満の点は買わない） ／ 0.55未満→3,000円（期待値の高い数点だけ）
  - e の計算は「的中確率×**取れている実オッズ**（無ければ推定オッズ）」を賭け金で重みづけ。前日夜の序盤オッズは薄い＝朝の実オッズで確定する
  - **紐（3着の相手）を足すかはレースごとに計算で決める**: 印のない馬を勝つ確率の高い順に最大2頭まで候補にし、足した点の平均期待値が 0.50 以上かつ既存の点の平均の90%以上なら足す。足すときは**1点の金額は据え置き**（点が増える分だけ予算が増える）。印は1頭ずつのまま（紐は印ではない）
  - 🔴 **印と買い目は必ず一致させる**（2026-10-31 ユーザー指摘「印があるのに買い目に無い／買い目にあるのに印が無い」）: 紐として足した馬には△を付ける（`predict_day.marks_and_bets`）。旨味が薄くて点数を絞るときも、印の付いた馬は最低1点は買い目に残す（`compose` の prune 後の補充）。投稿・画像を作る前に「印の馬の集合＝買い目に出る馬の集合」を確かめる
  - 根拠（`docs/keiba_himo_widening_20261031.md`）: 紐を広げると「何か当たる」は上がる（4.7→6.6%）が回収率は変わらない／穴軸の3連複で紐を広げると62〜77%と悪い。広げる目的は当たる頻度。`pattern_backtest.py`・台帳（ev_live・BUDGET=10,000）は比較のため従来の固定1万円のまま
- 🔴 期待値（的中率×オッズ）を必ず並べて書く。100%を下回る買い目は「参考」と明記
- 見送りのレースにも提示用の買い目は出す

### SNS（確立済み）
- 冒頭2行ヘッダー: `🏇【レース名 G2】YYYY年M月D日（曜）` ／ `━━ 競馬場 芝/ダXXXXm / XX頭 ━━`
- **印は1頭1行**（`◎ ⑱ダノンシーマ`）。印の直後に人気を書かない
- **買い目の投稿では、買い目の直前に全部の印を並べ直す**
- X は約140字・8行で折りたたまれる → 結論（印・勝つ確率・買い目・決め手✅）を上に、詳細は `─────` の下。**1本は500字前後まで・改行と余白を残す**（詰め込まない）
- 重賞は X7（結論／◎／○／▲／相手と穴／展開と馬場／買い目）・Threads6（500字以内）・note12セクション
- **（2026-10-10追加）1〜3番人気で◎○▲以外の馬は「人気馬をどう見たか」を1頭1投稿、人気より重い印（◎○▲で期待順位より3つ以上下の人気・🔥）は「人気と印のずれ」1投稿を足す**（本数は増えてよい）。理由の文は `draw_content.json` の `pop_view`。「評価を下げた＝負けると見ている、ではない」を必ず添える

## 5. 判定基準（事前登録・動かさない）

- ルール採用: 前向き台帳の累計が**300レース以上**で、レース単位の95%区間の**下限が100%超**。それまで実際には買わない
- ルール棄却: 100レース時点で、最高配当1レースを除いた回収率が80%未満
- 要素の採用: 年ごとの前向き検証で改善し、新しいレース（`fresh_test.py`）でも悪化しない
- 公開の買い目（型を当てはめる方式）は台帳とは別。**パターンを足す・条件を変えるときは `kaime_compose.PATTERNS` を直し、`pattern_backtest.py` で全区分（堅い/普通/荒れ×◎の人気）を測り直す**（結果は `db/pattern_segment_results.json` に積む）。標準形K2より回収率が5ポイント以上悪い型は、その区分で自動的に外れる（avoid）。旧V1.1の測定は `bet_structure_test.py`（`db/bet_structure_results.json`）
- 🔴 買い方を変えても回収率はほぼ動かない（2026-10-10: 6通りとも90.5〜93.1%）。回収率は印（確率）の質で決まる。買い方で選ぶのは「同じ回収率なら当たる頻度が高く振れ幅が小さい方」
- 次の候補（事前登録・2026-10-10）: ◎→○馬単（過去102.0%［93.6〜110.7］・人気馬が印なしのレースで106.2%）。同じ過去データで選び直さず、10/11以降の新しいレースの予想カード（cards_{日付}.json）で確かめる

# Debate SS - AIディベートスキル

## Overview

3人のAIペルソナが3ラウンドにわたってディベートを行い、
テーマに対する**多角的な視点**と**最終合意**を導き出すスキル。

Task toolのサブエージェントを使って3つの視点を並列で取得し、
メインコンテキストで統合・進行する軽量設計。

## When to Use

```
「〇〇についてディベートして」
「3人のAIで議論して」
「多角的に検討したい」
「/debate-ss」
「ディベートモードで考えて」
「賛否両論を出して」
```

## 引数

```
/debate-ss [テーマ]
/debate-ss [テーマ] --roles [役割1],[役割2],[役割3]
/debate-ss [テーマ] --rounds [ラウンド数(1-5)]
```

## デフォルト役割プリセット

### プリセット1: クリエイティブ（デフォルト）
企画・コンテンツ・マーケティング向け

| 役割 | 視点 | 口調 |
|------|------|------|
| 批判家（クリティカルシンカー） | 論理・正確性・リスク | 「それは本当に正しいのか？根拠は？」 |
| クリエイター（独創的な発想家） | 新規性・面白さ・感情 | 「もっとワクワクするアプローチがある！」 |
| マーケッター（現実的な戦略家） | 市場・ターゲット・ROI | 「で、実際に誰が見て、どう行動するの？」 |

### プリセット2: ビジネス
`--roles ビジネス` で選択

| 役割 | 視点 |
|------|------|
| CEO（経営者視点） | 収益・成長・ビジョン |
| CFO（財務視点） | コスト・リスク・ROI |
| CTO（技術視点） | 実現可能性・スケーラビリティ |

### プリセット3: ユーザー中心
`--roles ユーザー` で選択

| 役割 | 視点 |
|------|------|
| 初心者ユーザー | 分かりやすさ・ハードル |
| パワーユーザー | 機能性・効率・カスタマイズ |
| 離脱ユーザー | 不満点・改善要望・競合比較 |

### カスタム役割
`--roles 哲学者,科学者,芸術家` のようにカンマ区切りで自由に指定可能。

## 実行フロー

```
┌─────────────────────────────────────────────────────────┐
│  Phase 0: 準備                                          │
│  - テーマ確認                                           │
│  - 役割確定（プリセット or カスタム）                    │
│  - ラウンド数確定（デフォルト3）                         │
└─────────────────────────────────────────────────────────┘
        ↓
┌─────────────────────────────────────────────────────────┐
│  Round 1: 独立提案（Initial Proposals）                  │
│  - 3人が独立してテーマに対する見解を述べる              │
│  - 他の意見は見えない状態で自由に発想                   │
│  - Task sub-agents を3つ並列で起動                      │
└─────────────────────────────────────────────────────────┘
        ↓
┌─────────────────────────────────────────────────────────┐
│  Round 2: 批判的分析（Critical Analysis）                │
│  - Round 1の全意見を読んだ上で反論・補強・質問          │
│  - 他の2人の意見に対してツッコミを入れる                │
│  - 自分の意見も修正・深化させる                         │
│  - Task sub-agents を3つ並列で起動                      │
└─────────────────────────────────────────────────────────┘
        ↓
┌─────────────────────────────────────────────────────────┐
│  Round 3: 合意形成（Consensus Building）                 │
│  - Round 1-2を踏まえて最終見解を述べる                  │
│  - 譲れるポイントと譲れないポイントを明確化             │
│  - 他の2人との合意点を積極的に見出す                    │
│  - Task sub-agents を3つ並列で起動                      │
└─────────────────────────────────────────────────────────┘
        ↓
┌─────────────────────────────────────────────────────────┐
│  Phase F: 最終レポート                                   │
│  - メインコンテキストが3ラウンドを統合                  │
│  - 合意点・対立点・推奨アクションを整理                 │
│  - ユーザーに分かりやすく提示                           │
└─────────────────────────────────────────────────────────┘
```

## 実装上の注意

### サブエージェント起動ルール
- 各ラウンドで3つのTask sub-agentsを**並列**で起動する
- subagent_type は `general-purpose` を使用
- 各エージェントのmax_turnsは3以内（軽量に保つ）
- model は `sonnet` を使用（コスト効率）

### コンテキスト管理
- Round 1の出力 → Round 2のプロンプトに含める
- Round 1+2の出力 → Round 3のプロンプトに含める
- 最終レポートはメインコンテキストで生成

### エラーハンドリング
- サブエージェントが失敗した場合、メインコンテキストがその役割を直接実行
- タイムアウトは各エージェント60秒（十分な時間）
- 1人でも失敗したらそのラウンドの残りの結果で続行

### 例1: コンテンツ企画

```
/debate-ss Claude Codeを初心者向けに図解で説明する方法
```

### 例2: ビジネス判断
```

/debate-ss アプリのオンボーディングフロー改善 --roles ユーザー

```

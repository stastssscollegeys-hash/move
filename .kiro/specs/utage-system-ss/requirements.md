# Requirements: marketing-automation-system

> UTAGE + Lステップを中心に、国内外のMAツールの全機能を統合した、マーケティングオートメーションシステムの要件定義書。

## 1. 目的・概要（Executive Summary）
- マーケター・事業者が、LINE・メール・SMS・WhatsAppの4チャネルを統合し、ファネル構築から決済・会員サイト・ウェビナー・AIチャットボットまでを1つのプラットフォームで完結できるマーケティングオートメーションシステムを構築する。
- 国内ツール（UTAGE、Lステップ、エキスパ等）と海外ツール（ClickFunnels、GoHighLevel、WebinarJam等）の全機能を網羅し、AIによる自動化を加えた競合優位なシステムを目指す。
- 対象ユーザーは個人事業主から中小企業のマーケティング担当者。

## 2. 背景 & Context
- 現状、日本国内のマーケティングオートメーション市場では、UTAGE（ファネル+メール+決済）とLステップ（LINE配信+分析）が主要ツールだが、両者を併用する必要がある。
- 海外ではGoHighLevelやClickFunnelsがオールインワンで提供しているが、LINE対応がなく日本市場の要件を満たせない。
- 複数ツールの併用によるデータ分断、運用コスト増大、学習コスト増大が課題。
- AIチャットボット・AIアシスタントを統合したMAツールは国内外ともに存在しない。

## 3. スコープ
### 3.1 In Scope
- ファネルビルダー（LP・セールスページ・登録フォーム）
- マルチチャネル配信（LINE・メール・SMS・WhatsApp）
- ステップ配信・セグメント配信・一斉配信
- 決済機能（一括・分割・サブスクリプション・オーダーバンプ・アップセル）
- 会員サイト（コース・レッスン・ドリップ配信・進捗トラッキング）
- ウェビナー機能（ライブ・自動・ポップアップオファー・投票・Q&A・チャット）
- 予約管理（カレンダー予約・イベント予約・リマインダ）
- CRM/顧客管理（タグ・スコアリング・パイプライン）
- アフィリエイト機能（パートナー管理・報酬計算・承認）
- AIチャットボット・AIアシスタント・AIコピーライティング
- 分析ダッシュボード（KPI・ファネル分析・流入経路分析・クロス分析・A/Bテスト）
- ワークフローオートメーション（条件分岐・行動ベーストリガー）
- 管理者ダッシュボード

### 3.2 Out of Scope（重要）
- モバイルネイティブアプリ（Phase 1ではWebアプリのみ）
- ホワイトラベル・SaaS再販機能（将来Phase）
- 広告運用の自動入札・クリエイティブ生成
- ECサイト（カート・在庫管理・配送管理）
- 音声通話・コールセンター機能
- ソーシャルメディア投稿管理

## 6. 前提/仮定（Assumptions）
- LINE Messaging APIの利用にはLINE公式アカウント（認証済み）が必要。
- 決済はStripe APIを使用する（日本国内の手数料率3.6%）。
- メール送信はAmazon SES（$0.10/1,000通）を使用する。
- SMS/WhatsApp送信はTwilio APIを使用する。
- ウェビナーのライブ映像配信はZoom APIまたはWebRTCを使用する。
- AIチャットボットはClaude API（Haiku: $0.25/100万入力トークン）を使用する。
- 予約管理はCal.com（OSS）をセルフホストして統合する。
- 初期ターゲットは日本市場（日本語UI）。多言語対応はOut of Scope。
- 同時利用ユーザー数は最大1,000人を想定（Phase 1）。
- ウェビナーのライブ映像配信はPhase 1ではZoom APIを使用する（コスト面よりも開発速度を優先）。
- ホワイトラベル・SaaS再販機能はOut of Scope（将来Phase）。
- GDPRへの対応はPhase 1ではOut of Scope（日本市場のみ対象のため）。
- 決済代行サービスはPhase 1ではStripeのみ対応する。PayPal・UnivaPayは将来Phase。

## 7. 制約（Constraints）
- 技術: フロントエンドはNext.js 14+、バックエンドはNode.js（Hono）またはPython（F-API）を使用する。
- 技術: データベースはPostgreSQL（Supabase経由）、キャッシュはRedis、分析用はClickHouseを使用する。
- 技術: LINE Messaging APIのPushメッセージは2,000リクエスト/秒のレート制限がある。
- 技術: Twilio SMS送信は1セグメントあたり$0.0083の従量課金が発生する。
- 法務: 個人情報保護法に準拠し、顧客データを暗号化・アクセス制御して管理する必要がある。
- 法務: 特定電子メール法に準拠し、配信停止リンクの設置が必須。
- 法務: 特定商取引法に基づく表記が決済ページに必須。
- 運用: 月間固定運用コストを50,000円以下に抑える（1,000リード規模）。
- 外部API: Stripe Webhookのタイムアウトは30秒。
- 外部API: LINE Messaging APIの応答時間は1秒以内を目標とする。

## 9. 機能要件（Functional Requirements）

### 9.1 ファネルビルダー

### REQ-001: ファネルページのドラッグ&ドロップ作成
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、マーケターがドラッグ&ドロップ操作でファネルページ（LP・セールスページ・登録フォーム・サンクスページ）を作成できる機能を提供しなければならない。
- 根拠/目的: コーディング不要でページ作成を可能にし、マーケターの技術障壁を排除する。
- 受入テスト(GWT):
  - AT-0011: Given マーケターがファネルビルダーを開いたとき When テキスト要素をキャンバスにドラッグ&ドロップし、テキストを入力して保存ボタンを押す Then ページプレビューに入力したテキストが表示される。
  - AT-0012: Given マーケターがファネルビルダーでページを編集中のとき When 画像要素をドロップし、画像ファイル（JPEG/PNG/WebP、10MB以下）をアップロードする Then 画像がキャンバス上に表示され、ドラッグでサイズ変更・位置変更ができる。
- 例外・エラー:
  - EH-0011: If アップロードされたファイルが10MBを超える場合、システムは「ファイルサイズは10MB以下にしてください」というエラーメッセージを表示し、アップロードを拒否しなければならない。
  - EH-0012: If アップロードされたファイルがJPEG/PNG/WebP以外の形式の場合、システムは「対応形式はJPEG、PNG、WebPです」というエラーメッセージを表示しなければならない。
- 補足:
  - 対応要素: テキスト、画像、動画（YouTube/Vimeo埋め込み）、ボタン、フォーム、カウントダウンタイマー、プログレスバー、アコーディオン、カルーセル、区切り線、スペーサー

### REQ-002: ファネルページテンプレート
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、LP・ウェビナー登録・セールスページ・サンクスページの4カテゴリ、合計20種類以上のテンプレートを提供しなければならない。
- 根拠/目的: マーケターがゼロからデザインする手間を省き、コンバージョン率の高い実績あるレイアウトを提供する。
- 受入テスト(GWT):
  - AT-0021: Given マーケターが新規ファネルページ作成画面を開いたとき When テンプレート一覧を表示する Then 4カテゴリに分類された20種類以上のテンプレートが表示される。
  - AT-0022: Given マーケターがテンプレートを選択したとき When 「このテンプレートを使用」ボタンを押す Then テンプレートの内容がファネルビルダーに読み込まれ、編集可能な状態になる。
- 例外・エラー:
  - EH-0021: If テンプレートデータの読み込みに失敗した場合、システムはリトライを1回実行し、それでも失敗した場合は「テンプレートの読み込みに失敗しました。再度お試しください」と表示しなければならない。

### REQ-003: ファネルページのA/Bテスト
- 種別: EARS-オプション
- 優先度: SHOULD
- 要件文(EARS): A/Bテスト機能が有効な場合、システムは同一ファネルページに対して最大5つのバリエーションを作成し、指定した割合（合計100%）でトラフィックを分配しなければならない。
- 根拠/目的: データに基づいたページ改善を実現する。
- 受入テスト(GWT):
  - AT-0031: Given マーケターがファネルページのA/Bテストを設定するとき When バリエーションA（50%）とバリエーションB（50%）を作成し、テストを開始する Then 100アクセスのうち、バリエーションAに45〜55アクセス、バリエーションBに45〜55アクセスが分配される（許容誤差10%）。
- 例外・エラー:
  - EH-0031: If トラフィック分配割合の合計が100%でない場合、システムは「分配割合の合計を100%にしてください」というエラーメッセージを表示し、保存を拒否しなければならない。

### REQ-004: ファネルページの公開・独自ドメイン
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、作成したファネルページをシステム提供サブドメインまたはマーケターが設定した独自ドメインで公開できる機能を提供しなければならない。
- 根拠/目的: ブランディングに合わせたURL設定を可能にする。
- 受入テスト(GWT):
  - AT-0041: Given マーケターがファネルページを作成し「公開」ボタンを押したとき When システムサブドメイン（例: abc123.system-domain.com）で公開を選択する Then 5秒以内にそのURLでページがHTTPステータス200で表示される。
  - AT-0042: Given マーケターが独自ドメイン（例: landing.example.com）のDNS設定（CNAMEレコード）を完了したとき When ドメイン設定画面でドメインを入力し「検証」ボタンを押す Then DNS検証が成功し、SSL証明書が自動発行され、独自ドメインでページが表示される。
- 例外・エラー:
  - EH-0041: If DNS検証が失敗した場合、システムは「DNSレコードが確認できません。CNAMEレコードの設定を確認してください」と表示しなければならない。

### 9.2 マルチチャネル配信

### REQ-005: メールステップ配信
- 種別: EARS-イベント駆動
- 優先度: MUST
- 要件文(EARS): リードがメール配信リストに登録されたとき、システムは事前設定されたステップメールシナリオに基づき、指定された日時・間隔でメールを自動送信しなければならない。
- 根拠/目的: リード獲得後の自動ナーチャリングを実現する。
- 受入テスト(GWT):
  - AT-0051: Given 3通のステップメール（登録直後、1日後、3日後）が設定されたシナリオがあるとき When リードが2026-03-05 10:00にリストに登録される Then 1通目が2026-03-05 10:00〜10:05の間に送信され、2通目が2026-03-06 10:00〜10:05の間に送信され、3通目が2026-03-08 10:00〜10:05の間に送信される。
- 例外・エラー:
  - EH-0051: If Amazon SES APIが503エラーを返した場合、システムは30秒後にリトライし、3回失敗した場合はエラーログに記録し、管理者に通知メールを送信しなければならない。
  - EH-0052: If リードが配信停止を申請した場合、システムは即座にそのリードへの全ステップメール配信を停止しなければならない。

### REQ-006: メールセグメント配信
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、タグ・カスタムフィールド・行動履歴（メール開封・リンククリック・購入有無）の条件を組み合わせてセグメントを作成し、そのセグメントに限定してメールを配信する機能を提供しなければならない。
- 根拠/目的: ターゲットを絞った配信により、開封率・クリック率を向上させる。
- 受入テスト(GWT):
  - AT-0061: Given 「タグ=VIP」AND「過去30日以内にメール開封あり」のセグメントを作成したとき When そのセグメントに対して一斉メールを配信する Then タグVIPかつ過去30日以内にメール開封履歴のあるリードのみにメールが送信され、条件に合致しないリードには送信されない。
- 例外・エラー:
  - EH-0061: If セグメント条件に合致するリードが0件の場合、システムは「条件に合致するリードが0件です。条件を見直してください」と表示し、配信を実行しない。

### REQ-007: LINEステップ配信
- 種別: EARS-イベント駆動
- 優先度: MUST
- 要件文(EARS): ユーザーがLINE公式アカウントを友だち追加したとき、システムはLINE Messaging APIを使用し、事前設定されたステップ配信シナリオに基づきLINEメッセージを自動送信しなければならない。
- 根拠/目的: LINE友だち追加直後からの自動ナーチャリングを実現する。
- 受入テスト(GWT):
  - AT-0071: Given 2通のLINEステップ（友だち追加直後、1日後）が設定されたシナリオがあるとき When ユーザーが友だち追加を行う Then 1通目のメッセージが友だち追加から10秒以内にLINEに配信され、2通目が24時間後の指定時刻に配信される。
- 例外・エラー:
  - EH-0071: If LINE Messaging APIが429（レート制限）を返した場合、システムは5秒後にリトライし、3回失敗した場合はキューに入れて60秒後に再試行しなければならない。
  - EH-0072: If ユーザーがLINE公式アカウントをブロックした場合、システムはそのユーザーへの配信をスキップし、ブロック状態をDBに記録しなければならない。

### REQ-008: LINEセグメント配信
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、タグ・友だち情報・流入経路・カスタムフィールドの条件でセグメントを作成し、そのセグメントに限定してLINEメッセージを配信する機能を提供しなければならない。
- 根拠/目的: 全友だちへの一斉配信ではなく、ターゲットを絞った配信でメッセージ通数を節約する。
- 受入テスト(GWT):
  - AT-0081: Given 「流入経路=Instagram広告」AND「タグ=セミナー参加済み」のセグメントを作成したとき When そのセグメントに対してLINEメッセージを配信する Then 条件に合致する友だちのみにメッセージが送信される。
- 例外・エラー:
  - EH-0081: If セグメント条件に合致する友だちが0件の場合、システムは「条件に合致する友だちが0件です」と表示し、配信を実行しない。

### REQ-009: LINEリッチメニュー出し分け
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、友だちのタグ・属性・行動履歴に基づき、異なるリッチメニューを動的に表示する機能を提供しなければならない。
- 根拠/目的: ユーザーの状態に合わせたCTA表示により、コンバージョン率を向上させる。
- 受入テスト(GWT):
  - AT-0091: Given 「タグ=未購入」の友だちにはメニューA（セミナー案内）、「タグ=購入済み」の友だちにはメニューB（会員サイトリンク）を設定したとき When 「タグ=未購入」の友だちがトーク画面を開く Then メニューAが表示される。
  - AT-0092: Given 友だちのタグが「未購入」から「購入済み」に変更されたとき When その友だちがトーク画面を開く Then メニューBに切り替わって表示される。
- 例外・エラー:
  - EH-0091: If LINE APIのリッチメニュー設定APIがエラーを返した場合、システムはデフォルトのリッチメニューを表示し、エラーをログに記録しなければならない。

### REQ-010: SMS配信
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、Twilio APIを使用し、リードの電話番号に対してSMSメッセージ（最大660文字）を送信する機能を提供しなければならない。
- 根拠/目的: メール・LINEに加え、SMSチャネルによるリーチ拡大。
- 受入テスト(GWT):
  - AT-0101: Given マーケターが「電話番号=+819012345678」のリードに対してSMSメッセージ「セミナーのご案内です」を送信したとき When 送信ボタンを押す Then Twilio APIを経由してSMSが送信され、Twilioのステータスが「delivered」になる。
- 例外・エラー:
  - EH-0101: If Twilio APIがエラーコード21211（無効な電話番号）を返した場合、システムは「無効な電話番号です」と表示し、そのリードのSMS配信をスキップしなければならない。
  - EH-0102: If メッセージが660文字を超える場合、システムは「メッセージは660文字以内にしてください」と表示し、送信を拒否しなければならない。

### REQ-011: WhatsApp配信
- 種別: EARS-普遍
- 優先度: SHOULD
- 要件文(EARS): システムは、Twilio WhatsApp APIを使用し、テンプレートメッセージまたはセッションメッセージをリードに送信する機能を提供しなければならない。

### REQ-012: 配信停止（オプトアウト）

- 種別: EARS-普遍
- 優先度: MUST

  - AT-9021: Given DB内にリードレコードが100,000件存在するとき When リード一覧画面（ページネーション20件/ページ）を表示する Then 2秒以内に表示される。
- 例外・エラー:
  - EH-9021: If メール送信キューが10,000件を超えた場合、システムはワーカーを自動スケールアウトしなければならない。

### REQ-903: データバックアップ
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、データベースの完全バックアップを毎日1回自動実行し7日分を保持し指定されたバックアップから24時間以内に復元しなければならない。
- 根拠/目的: データ損失リスクの最小化。
- 受入テスト(GWT):
  - AT-9031: Given 7日前のバックアップが存在するとき When 管理者が復元操作を実行する Then 24時間以内にデータベースが7日前の状態に復元される。
- 例外・エラー:
  - EH-9031: If バックアップが失敗した場合、システムは管理者にアラートを送信し、1時間後にリトライしなければならない。

## 11. セキュリティ/プライバシー要件

### REQ-050: 認証・セッション管理
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、マーケター・管理者のログインにメールアドレス+パスワード認証を使用し、セッションの有効期限を24時間とし、不正ログイン試行を5回連続失敗でアカウントロック（30分間）しなければならない。
- 根拠/目的: 不正アクセスからシステムを保護する。
- 受入テスト(GWT):
  - AT-0501: Given ユーザーが5回連続で誤ったパスワードを入力したとき When 6回目のログインを試みる Then 「アカウントがロックされました。30分後に再度お試しください」と表示され、正しいパスワードでもログインできない。
- 例外・エラー:
  - EH-0501: If ロック中のアカウントに対してログイン試行があった場合、システムはそのIPアドレスと試行日時をセキュリティログに記録しなければならない。

### REQ-051: データ暗号化
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、通信をTLS 1.2以上で暗号化し、データベース内の個人情報（メールアドレス・電話番号・クレジットカード情報）をAES-256で暗号化して保存しなければならない。
- 根拠/目的: 個人情報保護法への準拠およびデータ漏洩リスクの最小化。
- 受入テスト(GWT):
  - AT-0511: Given システムへのHTTPSリクエストを行ったとき When SSL/TLSハンドシェイクを検査する Then TLS 1.2以上が使用されている。
  - AT-0512: Given DBの個人情報カラムを直接クエリしたとき When 暗号化されたデータを確認する Then 平文ではなく暗号化されたバイナリデータが格納されている。
- 例外・エラー:
  - EH-0511: If TLS 1.2未満の接続要求があった場合、システムは接続を拒否しなければならない。

### REQ-052: APIキー管理
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、外部APIキー（Stripe・LINE・Twilio・Claude等）を環境変数またはシークレットマネージャーに格納し、アプリケーションログにAPIキーを出力しない設計としなければならない。
- 根拠/目的: APIキーの漏洩を防止する。
- 受入テスト(GWT):
  - AT-0521: Given システムが稼働中のとき When アプリケーションログ全文を検索する Then APIキーのパターン（sk_live_*、Bearer *等）が1件も検出されない。
- 例外・エラー:
  - EH-0521: If ログにAPIキーパターンが検出された場合、システムはアラートを発報し、該当キーのローテーションを推奨しなければならない。

## 12. ログ/監視/運用要件

### REQ-053: アプリケーションログ
- 種別: EARS-普遍
- 優先度: MUST
- 要件文(EARS): システムは、全APIリクエスト（パス・メソッド・ステータスコード・レスポンスタイム）、メール/LINE/SMS送信結果、決済結果、ワークフロー実行結果を構造化ログ（JSON形式）で出力しなければならない。
- 根拠/目的: 障害調査・パフォーマンス監視の基盤。
- 受入テスト(GWT):
  - AT-0531: Given APIリクエストが処理されたとき When ログ出力を確認する Then JSON形式で{timestamp, method, path, status_code, response_time_ms, request_id}が記録されている。
- 例外・エラー:
  - EH-0531: If ログ出力先（ファイル/ログサービス）に書き込みできない場合、システムはstderrにフォールバック出力しなければならない。

### REQ-054: アラート通知
- 種別: EARS-イベント駆動
- 優先度: MUST
- 要件文(EARS): エラー率が5分間で1%を超えた、またはP99レスポンスタイムが5秒を超えたとき、システムは管理者にSlack/メールでアラートを送信しなければならない。
- 根拠/目的: 障害の早期検知と対応。
- 受入テスト(GWT):
  - AT-0541: Given エラー率モニタリングが有効なとき When 5分間のエラー率が1.5%に達する Then 管理者にSlack通知とメール通知が送信される。
- 例外・エラー:
  - EH-0541: If アラート通知自体が失敗した場合、システムはリトライを3回実行し、失敗をログに記録しなければならない。

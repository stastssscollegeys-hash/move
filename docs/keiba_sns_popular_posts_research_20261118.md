## 5. 4つに共通していること

1. **予想そのものより、「馬・人・出来事の物語」と「ニュース」が広く届く**（X・Threadsで顕著）
2. **切り口を1つにしぼった発信者が強い**（血統・追い切り・展開・指数）
3. **レースの前だけでなく、後（結果報告・回顧）が読まれ、見られている**
4. **サービスごとに合う形が違う**: X＝短文＋動画/画像、Threads＝短い文字と気持ち、YouTube＝人物と切り口、note＝専門の深掘りと回顧
5. 実績を見せる人が多い。ただし、当たった分だけ見せる・後出しは疑われる、という指摘がある（予想家の比較記事）

## 6. アスメシ競馬予想で試すこと（提案）

いまの発信は「長い構成の予想」が中心で、X・Threadsの人気の形（短い・物語・ニュース）とずれている。予想の質は変えずに、入口を足す。

### すぐ試せること
- **X: 「1頭の紹介」の短い投稿を足す**（80〜140字＋画像1枚）。例:「ガイアフォース。古馬のマイルG1で3戦続けて2着。今回は168日ぶり。7歳以上は過去10年で3着内なし」。買い目は入れない。長文の予想は、そのあとに続ける
- **X・Threads: ニュースに早く反応する**（回避・次走・乗り替わり・引退）。事実1行＋こちらのデータ1行
- **Threads: 短い文字の投稿を1日1〜2本**。一言の見立て、節目の数字、問いかけで終える（「この馬、買いますか？」）。いまの長い投稿は本数を減らす
- **Threads: 一覧もの**（出走予定と騎手・指数の上位5頭）を1本
- **題名に「気になる一言」**: 【レース名＋年】のあとに、意外な数字や問いを置く（すでに YouTube と note で実施。継続）

### 少し手間がかかること
- **結果報告・回顧を必ず出す**（当たりも外れも）。動画は短くてよい。note は「なぜ◯◯だったのか」の題名で
- **切り口を「独自指数」に固定して、名前で覚えてもらう**（指数の順位と結果を毎週並べて見せる）
- **新しい見せ方を1つ持つ**（例: 指数ランキングの動く図、展開の図）
- **note と X の連動**（note の一部を X の投稿で先に見せる）

### しないこと
- **当たった分だけを見せる・後から買い目を出す**。信用を失う。事前に出して、結果は全部報告する（いまの方針のまま）
- **レース映像や他人の写真の転載**。権利の問題がある。人気の投稿の多くは映像を使っているが、こちらは自作の画像と図で作る
- 伸びているアカウントの丸写し

### 確かめ方
- 2〜3週間、上の「すぐ試せること」を足して、投稿ごとの表示・いいね・返信・フォロワーの増減を記録する
- 形式（短文＋画像／長文／一覧／ニュース反応）ごとに比べ、伸びた形だけ残す
- 1週間ぶんの抜き取りから出した仮説なので、数字で確かめてから決める

### 7-4. 真似できるか

| 人気の形 | 真似できるか | 理由・やり方 |
|---|---|---|
| データ1枚＋問いの題（◯◯って荒れるの？） | ◎ すぐできる | 過去10年の集計はすでにある（race_profile）。問い1つ＋数字3つ＋画像1枚にするだけ |
| 1頭の物語（戦績・縁・ラストラン） | ◎ すぐできる | 近走と成績は手元にある（entry_digest）。写真の代わりに自作の画像 |
| 次走・回避・乗り替わりのニュース | ○ できる | 報道を確かめて、事実1〜2行＋こちらのデータ1行。出典を確かめる手間がある。速さでは報道機関に勝てない |
| 短い投稿を1日じゅうばらして出す | ○ できる | 文は作れる。投稿するのはユーザー（下書き）。予約投稿を使うかはユーザーの判断 |
| 題名を「問い1つ」「意外な数字」にする | ◎ すぐできる | こちらの数字でも伸びている |
| 1レースを複数本の動画に分ける | ○ できる | いまの本編（約10分）を「データ編」「軸候補編」「穴馬編」に分けられる。作る本数は増える |
| ショートを増やす | ◎ すぐできる | いちばん見られている。1頭1本・データ1つ1本にできる |
| 結果報告・回顧 | ○ できる | 結果の取得と採点の道具はある。当たりも外れも出す |
| ひとこと・冗談・あいさつ | △ ユーザーしだい | 人柄が出る投稿。アスメシくんの口調で作ることはできるが、本人の言葉のほうが伝わる |
| レース映像・パドック映像・関係者の動画 | × しない | 権利の問題。人気の投稿の多くはこれだが、真似しない |
| 顔と名前を出す・複数人で話す | × いまは無い | 人物の魅力で見られている型。代わりに「独自指数」と「アスメシくん」で覚えてもらう |
| 当たりの強調（特大回収・◯週連続的中） | × しない | 当たった分だけ見せると信用を失う。こちらは前向きに記録した結果だけを書く |

### 7-5. まず2週間、試す形（案）

1. X: 1レースにつき「データ1枚＋問い」2本・「1頭の物語」3本を、時刻をばらして出す。リンクは本文に入れず、返信に付ける形も試す
2. ショート: 1レース1本から、「データ1つ」「1頭」で2〜3本に増やす。題名は意外な数字か問い
3. 本編: 題名を「問い1つ」に変える（例:「なぜ、想定1番人気を軸にしないのか」）
4. Threads: 短い文字の投稿（一言の見立て＋問いかけ）を1日1〜2本
5. 記録: 投稿ごとに形式・表示・いいね・返信を付け、2週間後に形式ごとに比べる

  テーマは「注目の1頭｜馬名」「気になるデータ｜脚質」のように短く。画像の上の帯だけは短い形（レース名 格｜日付）のまま
- 下書きの文の差し替え: X は下書き一覧の行を JS の click() で開く → 実キーで ctrl+a → BackSpace → ctrl+v → 閉じる → 保存（execCommand の selectAll/delete は使わない＝古い文が残って混ざった）。
  Threads は 新しいスレッド → 下書き → 行を JS の click() で開く → 入力欄に focus → ctrl+a → BackSpace → ctrl+v → キャンセル → 「更新」。どちらも画像は残る
- 報道で確かめられなかった話（アラタの引退・マリアイリダータの除外）は書かなかった
- 🔴 X の画像添付: 投稿画面（/compose/post）には file input が2つある（後ろのホーム画面の入力欄にもある）。そのまま find で拾うとホーム側に画像が付き、下書きは文だけで保存される。
  対策＝先に `input[type=file]` のうち `[role=dialog]` の外にあるものを消してから find → file_upload。保存前に、ダイアログ内の画像が1枚・本文の字数を確かめる
- Threads は投稿画面の file input が1つだけなので、そのまま添付できる（キャンセル → 保存）
- 次にすること: 投稿後、形式（1頭の物語／データ＋問い／これまでの長い投稿）ごとに表示・いいね・返信を記録して比べる

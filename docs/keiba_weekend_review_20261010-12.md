## 3. 馬場バイアス（連休3日間）と、そこから分かったこと

連休の傾向（日→日）:
- 京都: 芝・ダートとも時計が出る馬場で、**逃げ・先行が優勢、外枠は不利**が3日間続いた
- 東京芝: 流れが速く、差し・追い込みと外枠が届く日（日曜）／月曜は逃げ1.53倍と変化。東京ダートは日ごとに入れ替わった

**前日の傾向が翌日も同じ側に出たか**（この3日・前日に1倍から0.2以上離れていた区分）: 34件中23件（68%）。逃げ・先行は続きやすく、中枠は続かなかった。

これを10年・約25万頭で確かめた（`daybias_test.py`・同じ開催の連続開催日・同じ柵・リークなし）:

| | 前日が内有利→翌日の内枠馬（人気からの期待に対する実際） | 前日が内不利→翌日の内枠馬 | 差 |
|---|---|---|---|
| 芝・前半(2016-21) | 1.035 | 0.948 | +8.7pt |
| 芝・後半(2022-26) | 1.067 | 0.998 | +6.9pt |
| ダ・前半 | 0.981 | 0.860 | +12.2pt |
| ダ・後半 | 0.940 | 0.899 | +4.2pt |

→ **内枠の馬は、前日の内外の有利不利を翌日に引きずる**（前半・後半とも同じ向き。芝の「前日内有利」は全期間 z=+2.89・11年中9年で1超）。
一方、**前で運ぶ型は芝で向きが安定しない**（前半 +4.7pt／後半 −5.2pt）＝使わない。これまでの結論（脚質・ペースは当てにくい）と整合する。

→ `factor_candidates.json` に「内枠×前日の内外の有利不利」を事前登録（gate_passes=1・eval_from=20261013）。**確率にはまだ入れない**。
  入れる前に `ev_engine.py --walk`（年ごとの前向き）と、20261013以降の新しいレースでの2回連続通過が必要（SKILL §2）。

### 3b. 年ごとの前向き確認（2026-10-13・`daybias_test.py`）

ルールは固定値（内枠の前日の偏りが ±0.06 以上）で、年ごとに学習する部分が無いため、毎年が未使用データとして見られる。

| | 差がプラスの年 | 直近3年(2024-26) | 年ごとの範囲 |
|---|---|---|---|
| 芝 | **9/11年** | 前日内有利1.055／内不利0.994 → +6.2pt | −4.5〜+16.9pt |
| ダ | **9/11年** | 前日内有利0.981／内不利0.916 → +6.5pt | −5.9〜+22.2pt |

- 外れた年: 芝 2018・2019、ダ 2022・2026。向きは毎年そろうわけではない。9/11 の偶然確率は約3%（片側）。
- ダートの内枠は、前日がどちらでも人気の期待を下回る（0.88〜0.98）。見るべきは**絶対値でなく差**。
- 効果の大きさは 3着内 +3〜5% 程度で、単勝・馬連の回収率に直すと控除率を超えるか不明。
- しきい値 ±0.06 は全期間を見たあとに決めた値なので、**これは在サンプル**。判定は 20261013 以降の新しいレースで行う。
- → 確率には入れない。次の週末から `day_review` の JSON に前日の内枠の偏りを残し、候補の2回連続通過を前向きで見る。

### 3c. 確率モデルに足した場合の前向き検証（2026-10-14・`walk_prevday_test.py`）

「前日の内枠有利度×内枠／×外枠」を特徴量に足し、年ごとの前向き検証（2019〜2026・35,575レース）で現行と比べた。

| | 対数尤度差（市場との差） | EV≧1.0・10倍以下の回収率 | EV≧1.05・10倍以下 |
|---|---|---|---|
| 現行 | +0.00601 ［+0.00469, +0.00733］ | 109.1% ［99.1〜119.5%］ | 113.2% ［95.8〜129.9%］ |
| 前日の内枠有利度を追加 | +0.00605 ［+0.00472, +0.00737］ | 109.6% ［99.7〜120.0%］ | 115.7% ［98.1〜132.6%］ |

- 差は +0.00004/レース。年ごとに見ても 6/8年で微増だが、いずれも誤差の範囲（調教の採用時は +0.0005）。
- 年別の差（内枠の超過+3〜5%）は確かにあるが、**人気に既に織り込まれている**ため、確率を動かすほどの情報にはならない。
- → **確率には入れない。採用しない**（フラグ `PREVDAY=1` のときだけ使える形で残す）。説明文（`trends`）での表示にとどめる。
- 現行モデルの年ごとの前向き検証は 8年すべてで対数尤度差がプラス（+0.0037〜+0.0093）。回収率は10倍以下・EV≧1.0 で区間の下限が99%台＝採用基準（100%超）の手前。

## 5. 運用で分かったこと（再発防止）

1. **月曜祝日の平場は、土曜夜は枠順が未確定**（日曜に出る）。重賞しか計算に入らない → 平場の本計算は日曜夜。
2. `odds_snapshot.py` の出力を `| Select -First 10` で打ち切ると途中で止まり、後半の競馬場が前夜の予想オッズのままになる。出力はファイルに落とす。
3. `ev_live.py` が MemoryError（履歴を2回メモリに載せる）。`train_all()` の戻りの `hist_rows` を件数だけ取って捨てれば通る。**本体は 2026-10-13 に修正済み**（ブランチ `worktree-keiba-word-order` の aa64ab7。`train_all()` が件数だけ返す）。作業ブランチへ取り込むまでは古い ev_live のまま。`raceday_auto.py` は ev_live を子プロセスで呼ぶので、直さないと自動運転が落ちる。
4. 「期待値の取れるレース」は**当日朝の実オッズで判定**する。前日の想定オッズの期待値は参考扱い（東京3Rは勝負馬連が朝の実オッズで0.77に下がった）。
5. `weekend_pdca.py` は「標準」の買い目の収支を表示しない（kind が 標準 のとき集計のみで出力しない）。→ `weekend_review.py` で補完。
6. 生成文の日付ラベル「先週（10/10）」は誤り（連休では一昨日）。リステッドは `gen_flat_sns.py` の対象外で `draw_content.json` に手書きしないと投稿案が出ない。
7. 前向き台帳(E2.0)に載ったのは7点だけ（`raceday_auto.py` を回していなかった）。次の週末は自動運転で台帳を溜める。

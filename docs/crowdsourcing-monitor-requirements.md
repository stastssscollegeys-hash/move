# クラウドソーシング案件自動監視・通知システム 要件定義書

作成日: 2026-02-24
作成者: 清水昴

---

## 1. プロジェクト概要

クラウドワークス・ランサーズ・ココナラの案件を自動監視し、
特定ジャンルの新着案件をお客さんのLINE/Discordに通知するシステム。

お客さんは通知を受け取るだけ。管理は清水が行う。

---

## 2. 対象サイト

- クラウドワークス（crowdworks.jp）
- ランサーズ（lancers.jp）
- ココナラ（coconala.com）

3サイトとも公式API・RSSは存在しない（調査済み）。
公開ページへのHTTP Requestでデータを取得する。

---

## 3. 機能要件

### 3-1. 案件取得

- 3サイトの公開検索ページから案件情報を取得する
- 取得間隔: 15分毎
- 取得項目:
  - 案件タイトル
  - 案件URL
  - 報酬（金額・報酬体系）
  - カテゴリ
  - 掲載日
- お客さんが指定したキーワードで検索ページをフィルタする

### 3-2. ジャンルフィルタ（AI分類）

- GPT-4o-miniのText Classifierで案件をジャンル分類する
- お客さんの興味のあるジャンルにマッチした案件のみ通知する
- カテゴリ例（お客さんと要相談）:
  - ライティング・記事作成
  - Web開発・コーディング
  - デザイン・イラスト
  - データ入力
  - AI・ChatGPT関連
  - マーケティング・SNS運用
  - 対象外（通知しない）

### 3-3. 新着判定（重複排除）

- 案件URLまたは案件IDで過去通知済みの案件を管理する
- 同じ案件を2回通知しない

### 3-4. 通知

- 通知先: Discord Webhook または LINE Messaging API（お客さんと要相談）
- 通知内容:
  - 案件タイトル
  - 案件URL（リンク）
  - 報酬
  - 分類されたジャンル
  - 掲載サイト名

---

## 4. 非機能要件

### 4-1. 稼働時間

- 24時間365日稼働
- Railway上にデプロイするため、清水のPC起動状態に依存しない

### 4-2. スクレイピングの法的対応

- 公開ページ（ログイン不要）のみを対象とする
- robots.txtに従う
- リクエスト間隔を15分以上空ける（サーバー負荷を最小化）
- 取得データは案件選定目的のみに使用し、再配布しない
- 各サイトの利用規約を遵守する

### 4-3. エラー時の挙動

- サイトの構造変更等でスクレイピングが失敗した場合、清水に通知する
- お客さんへの影響を最小化する（エラー通知はお客さんに送らない）

## 5. 技術構成

### 5-1. アーキテクチャ

```
Railway（Hobbyプラン $5/月）
└── n8n（SQLite版）
    ├── Schedule Trigger（15分毎）
    ├── HTTP Request（3サイトの検索ページ取得）
    ├── HTML Extract（Cheerio: 案件データ抽出）
    ├── Text Classifier（GPT-4o-mini: ジャンル分類）
    ├── Remove Duplicates（新着判定）
    └── Discord Webhook / LINE Messaging API（通知）
```

### 5-2. 技術選定理由

n8n単体を選定した理由:
- GUIで管理可能（清水がブラウザから設定変更できる）
- スクレイピング・AI分類・通知を1サービスで完結
- Railwayにワンクリックデプロイテンプレートあり
- 月額$5で安定運用可能
- 他のお客さんへの横展開が容易

Playwright/ヘッドレスブラウザを不採用とした理由:
- クラウドワークス・ランサーズはHTTP Requestで取得できる可能性が高い
- 不要なコンテナを増やさず、コスト・複雑性を最小化
- もしココナラ等でHTTP Requestが不可だった場合のみBrowserlessを追加する

### 5-3. SPA非対応時のフォールバック

HTTP Requestで案件データが取れないサイトがあった場合:
- RailwayにBrowserlessを追加（+月$2〜5）
- n8nからBrowserless経由でPlaywrightレンダリング

  - 通知先の変更対応

## 9. 実装フェーズ

### Phase 1: 検証（PoC）
- 3サイトにHTTP Requestを投げて、HTMLが取れるか検証
- 取れる場合のHTML構造を確認し、CSSセレクタを特定

### Phase 2: プロトタイプ
- RailwayにN8nをデプロイ
- クラウドワークス1サイトでスクレイピング→通知の動作確認

### Phase 3: AI分類追加
- GPT-4o-miniのText Classifierノードを追加
- ジャンル分類のプロンプト調整

### Phase 4: 全サイト対応
- ランサーズ・ココナラを追加
- SPA対応が必要な場合はBrowserless追加

### Phase 5: 納品・運用開始
- お客さんの通知先に接続
- 動作確認後、運用開始

---

## 10. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| サイトの構造変更 | スクレイピングが失敗する | 清水に即時通知。CSSセレクタを修正 |
| アクセスブロック | IPがブロックされる | 15分間隔を守る。User-Agentを適切に設定 |
| 利用規約変更 | スクレイピングが明示禁止される | 該当サイトの監視を停止し、お客さんに報告 |
| Railway障害 | 全体停止 | Railway Status監視。長期障害なら別基盤に移行 |
| LINE Messaging API有料化 | コスト増 | Discord移行を提案 |

## 付録: 調査資料

### 各サイトのAPI/RSS状況（2026年2月調査）

- クラウドワークス: API なし。RSSは2018年末に廃止。SPA構成だがHTTP Requestで取得可能な報告あり
- ランサーズ: API なし（限定的なものはあるが案件検索は非公開）。RSS なし
- ココナラ: API なし。RSS なし。スキルマーケット形式
- その他日本のクラウドソーシング（シュフティ、ビズシーク、サグーワークス等）: 全てAPI/RSSなし。ビズシーク・サグーワークスはサービス終了済み

### 参考になるOSS・事例

- freelance-job-notifier（GitHub: hoosnick）: Python + APScheduler + SQLite + Telegram通知
- n8n公式テンプレート「Automated Web Scraper: Job Monitor With Telegram Alert」
- note記事「GASで副業情報を自動収集・通知するツール」（マリモのごはん）
- Qiita記事「コピペでスクレイピング: クラウドワークスの新着情報を収集」

### 法的整理

- 公開ページのスクレイピング自体は違法ではない
- 著作権法第30条の4（情報解析目的）の例外あり
- robots.txt遵守 + 低頻度 + 再配布なし → 法的リスクは低い
- 2024年7月の文化庁ガイダンスでrobots.txt無視は不法行為の可能性を示唆
- 過度な負荷は偽計業務妨害罪に該当する可能性あり（Librahack事件の前例）

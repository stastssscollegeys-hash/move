# 買い目パターン集（レースの型に合わせて当てはめる）— 2026-10-30

ユーザー指示（2026-10-30）: 「買い目の構成は、本来は必要な数だけパターンを用意したい。最近は同じパターンしか出てこないので、
レースごとにそのパターンを当てはめて買い目を構成する仕組みにしてほしい」

## 何が起きていたか
- 2026-10-10 から公開の買い目は V1.1（単勝◎＋馬連◎-○＋ワイド◎流し）の固定形で、全レース同じ形だった
- 過去に「型を判定して買い方を選ぶ」仕組みは3回作られた（`gen_kaime_v5.py` 53種／`kaime_patterns.py`＋`kaime_select.py`／`race_type_v63.py`）が、
  どれも毎日の予想（`predict_day.py`）の流れに入らず、固定形に戻った。今回は `predict_day.marks_and_bets` の中に組み込んだ

## 仕組み
1. `kaime_compose.make_ctx` がレース前の情報だけで特徴を作る（◎の勝つ確率・○との差・堅い/荒れ・頭数・◎の人気・🔥の有無）
2. `kaime_compose.PATTERNS` の `applies` に当てはまる型を、優先順位（prio）の小さい順に並べる。`K2` は必ず最後に残る
3. `pattern_segment_results.json` に「その区分で標準形K2より回収率が5ポイント以上悪かった型（avoid）」があれば外す
4. 同じ日に同じ型が3回以上続いたら、次点のうち使用回数が少ない型を使う
5. 賭け金は `allocate`: 重み×(1/オッズ)^指数。指数1だと「どの点が当たっても戻りが揃う」配分でガミ点を避ける。100円単位・合計1万円
6. 買い目の見出しに「買い方の型：◯◯」と理由を出す（`ref_bets` の `pattern`・`pattern_name`・`pattern_why`）

## 検証（2019〜2026・24,927レース・実払戻・年ごとの前向き予測）— `pattern_backtest.py`
- 型の使われ方（K11・K12追加後）: K5 25.5%／K4 21.2%／K11 12.2%／K9 8.8%／K2 7.7%／K10 5.3%／K3 5.1%／K1 4.7%／K12 3.2%／K6 2.8%／K7 2.8%／K8 0.8%
- 同じレースで比べると:

| | 型を当てはめる | 全レース標準形（K2） |
|---|---|---|
| 回収率 | 94.4% [91.9〜96.9] | 91.4% [89.7〜93.0] |
| 何か当たる | 41.9% | 48.1% |
| 当たったのに元が取れない（ガミ的中） | 25.5% | 27.9% |
| ガミ無しで当たる | 31.2% | 34.7% |

- 年別（型を当てはめる／標準形）: 19:99/94 20:89/89 21:99/95 22:95/92 23:94/91 24:94/90 25:92/91 26:91/89。K11・K12（馬単・3連単を入れた型）を足すと、回収率は 92.2%→94.4%
- **K11（3連単◎1着固定）は、当てはまる全レース（7,768R）で 99.5%、標準形は92%。前半2019〜22年も後半2023〜26年も 99.5%・年別 111/87/101/100/100/99/97/102**。普通で◎2〜3番人気の区分だけ見ると 124.4%［103.8〜146.5］だが、約80通りの組み合わせから目立ったものなので過信しない。🔴まだ100%を超えると言える根拠は無い（3連単λの過去の例では、発見130%→確認99%になった）
- 🔴 型の違いだけでは回収率はほとんど動かないが、馬単・3連単で ◎が勝った時の配当を取る型は、今回の検証では他より高かった。前向き（`ref_bets[].pattern`）で確かめる。
  変わるのは当たり方（小さく当たる回数が減り、大きく当たる回数が増える）。回収率は印（確率の質）と「買う/買わない」の判断（B1ルール・台帳）で決まる
- 🔴 型の判定条件と閾値は、この同じ24,927Rの分布を見て決めた（区分ごとの回収率の差は選ぶ根拠にしていない。使ったのは「明らかに悪い型を外す」安全装置だけ）。新しいレースで確かめるため、
  `cards_{日付}.json` の `ref_bets[].pattern` に型が残る。毎週の振り返りで型ごとの成績を前向きに集計すること

## パターンの足し方
1. `kaime_compose.py` に `_b_◯◯(M, c)`（[(券種, [馬番], 重み)] を返す）を書き、`PATTERNS` に `dict(id, prio, name, alloc_exp, build, applies, why)` を足す
2. `python pattern_backtest.py` で全区分を測り直す（結果は `db/pattern_segment_results.json` に積まれる）
3. 標準形K2より回収率が5ポイント以上悪い区分では自動で外れる。型の使われ方が偏りすぎていないかも見る

# ユーザーの予想の考え方（口述の記録・随時追記）

2026-11-01 から、ユーザーが口頭で話した「予想で大事にしていること」を順に記録し、エンジン（`ev_engine.py` の特徴量）への落とし込み状況を対応づける。
音声入力のため言い回しは整理してある。**採用の可否は従来どおり前向きの検証（同じ人気帯で差が出るか・モデル確率に無い情報か）で決める**。

## 前提（買う・買わないの判断）
- 期待値が大事。まず「買えるレースか・買える馬券か」を考える。
- 回収率の概念も大事（目的は年間回収率100%超）。→ 現状反映済み（勝負レース制・E2・B1台帳）。

## 1. 馬の実力（予想のまず一点目）

| 見ること | 現状 | 状況 |
|---|---|---|

### この点から出る検証候補（未実施・事前登録してから前向きで測る）
1. **相手関係**: 前走のレースで、同じレースに出ていた他馬の「その後3走の成績」（レースレベル指標）を馬の特徴量にする。
2. **馬ごとのラップ型**: 直近走の「前半3F÷後半3F」のバランス、減速率を馬の特徴量にする（ペース適性の代理）。
3. **馬ごとのバイアス適性**: 過去に内有利・外有利の日に、その馬が好走した度合い。

## 3. 総合点→期待値で買い目→年間収支をプラスに／最新情報の取り込み
ユーザーの全体像（口述）: これまでのファクター（旧17因子ほど）で総合点を付け、期待値に沿って最も期待値の取れる買い目を選び、年間の収支をプラスにする。期待値の計算には最新の情報を入れる。

**全体像との対応**
- 旧17因子の総合点（`factor_audit_v2.py`の対象）は、2026-09の監査で「市場に無い情報を持たない」と分かり、現行 v5.1 では**市場オッズを土台に調教・過去走・傾向を足した確率モデル**（`ev_engine.py`・71特徴量）に置き換え済み。総合点は「割安さ（モデル確率÷市場確率）」の順で印になる。
- 期待値→買い目: `ev_live.py`（実オッズで期待値）→`kaime_compose.py`（型別の買い目・予算可変・印と買い目の一致）。年間収支の判定は前向き台帳（E2.1・U1・B1）。

| 最新情報（口述） | 現状 | 状況 |

| 前日のペース・タイム（どういう時計になったか） | 時計の指数は馬場差補正つき（特徴量54〜56）。前日のペース・時計は`day_review`の「馬場の特徴」で出す | 時計は反映済み／前日のペースは説明用 |
| 厩舎コメント | **無い**（JV-Linkに含まれない。収集元は競馬ラボ・netkeiba等のWeb） | 不足 |

### この点から出る検証候補（未実施）
1. **新聞の印の集計**: 競馬新聞・予想サイトの印（◎の本数）を、レースごとに集めて「印の集中度」を特徴量にする（人気に織り込み済みかを同じ人気帯で検定）。収集元と取得可否の確認が先。
2. **厩舎コメントの強気・弱気**: Webのコメントを収集し、強気度を特徴量にする（追い切りの文章評価と同様、LLM採点が78%程度という実績あり）。
3. **追い切りの乗り手区分と、同日の全体順位**: JVの調教データ（HC/WC）に区分があれば、特徴量59〜64に追加して検証。
4. **SNSの注目度**: 注目の集中（言及数の偏り）と人気の乖離。収集の手間が大きいので優先度は低い。

## 4. 過小評価の馬を拾い、過大評価の馬を軽視する（ユーザー: 競馬で一番考えやすい核心）
口述: 前走で不利があった／ペースが合わなかった／トラックバイアスが合わなかった、という理由で負けただけの実力馬は人気がつかない。そういう人気薄の過小評価馬をどれだけ拾えるか、逆に過大評価（恵まれて好走しただけ）の馬をどれだけ軽視できるかが勝負。その上で期待値と馬券を考える。

**位置づけ**: これは現行の「割安さ（モデル確率÷市場確率）」の印そのもの。足りないのは「前走の負けは実力か不利か」を測る入力。

**検証した（`hypo_bias_prev.py`・2016〜2026の約44万頭）**: 前走の当日の【同じ日・場・芝ダの他レース】から、その馬の脚質×枠が有利/不利だった度合い D を作り、逆風で負けた馬(D≦0.75・前走6着以下: 67,531頭)と追い風で好走した馬(D≧1.30・前走3着以内: 18,957頭)の次走を測った。

| | 人気との比較（同じ人気帯） | モデルの勝率との比較 | 単勝回収 |
|---|---|---|---|
| 逆風で負けた（拾いたい側） | 3着内率は期待よりやや低い（z=−2.68）。人気薄(10人気以下)は差なし | 勝ち1604 vs モデル期待1531（z=+1.99）・市場期待1487 | 71% |
| 追い風で好走（軽視したい側） | 差なし（z=+0.36）。10人気以下だけ逆向き(+) | 勝ち2080 vs モデル期待2167（z=−2.19）・市場期待2201 | 72% |

結論:
- **逆風で負けた馬を拾う作戦は、この測り方では儲からない**（単勝71%、人気との比較で上振れなし）。市場はこの種の「不利負け」を既に値段に織り込んでいる。
- 恵まれ好走の馬は、モデルも市場も勝ち数を4〜5%過大評価する傾向（軽視の方向）。ただし弱く、人気との比較では出ない → `factor_candidates.json` に事前登録（down・eval_from=20261101・gate_passes=0）。2回連続で前向きに再現するまで使わない。
- **測れていないもの**: 実際の「不利」（進路の詰まり・接触・不利の映像評価）と、ペースが合わなかったか。JVのデータに不利の記録は無く、公開の不利情報（Winsight等）は会員限定。バイアスと位置取りの代理でしか測っていない。

### この点から出る検証候補（未実施）
1. **不利の記録の入手**: レース映像のコメント（競馬ラボ等のレース回顧）から「不利」「詰まる」「前が壁」を自動抽出し、LLM採点で列にする（追い切り文章の採点が78%だった実績あり）。
2. **ペース不利の代理**: 前走のペース（前半3F）に対して、その馬の位置取りが合っていたか（ハイペースで前にいた／スローで後ろにいた）。
3. 恵まれ好走の軽視候補を、台帳（B1・E2）の結果でクラス別に見る。

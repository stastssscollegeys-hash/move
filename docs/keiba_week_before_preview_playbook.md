## 2. 投稿の型（ユーザー指示・変えない）

1. **先頭は必ずレースの定型見出し**（文言固定）
   `🏇【レース名 G2】11月7日（土）` ／ `━━ 東京 芝1400m／登録10頭 ━━`
2. **その次にその投稿のテーマを1行**（「今回のテーマ」などの前置きは付けない）
   例: 過去10年から拾った「面白いデータ3つ」／注目馬の短評と「軸候補」／来週狙える「穴馬の型」と該当馬
3. **「先に結論」を2〜3行**（軸候補はこの馬／穴の型に合うのはこの馬／このデータが肝）
4. 本文。各馬は「▶一行結論」「近走」「◎狙える理由」「△気になる点」の順。**理由は厚く**（前走内容・通過順・上がり・間隔・斤量の増減・コース実績・調教をふだんと比較）。理由と懸念は必ずセット
5. 末尾 `#競馬予想 #AI予想 #JRA`
- 導入の投稿だけは定型見出しなし（3レースの結論一覧を最初に出す）
- **X**: 認証アカウントは長文可（約25,000字）。1本1,000〜2,000字まで（長すぎると折りたたまれる）。近走は全部載せる
- **Threads**: 500字以内。1頭1投稿。結論の行→近走の行の順に、入らなければ後ろから削る（`posts.py` が自動調整）
- **印・買い目は出さない**（枠順・オッズの後）。軸候補は「現時点の見立て」と書く
- 本数は圧縮しない（ユーザー指示: 増やしてよい）

## 3. 言葉づかいの決まり

- 「穴」「穴の型」は**想定6番人気以下の馬だけ**。想定人気が取れない週は「穴の型（人気要確認）」と書き、投稿前にオッズで確認する
- 人気の中心になる馬は「人気の中心候補」（ドゥラドーレス=想定2番人気を穴と書いて指摘された。メモリ `feedback_keiba_ana_must_be_low_popularity`）
- 前走1番人気だった馬を穴に入れるときは「前走1番人気なので今回の人気に注意」を付ける
- 騎手は「想定○○（報道）」。個人名・チャンネル名は投稿に出さない（インフルエンサー等）
- **「〇〇組」の頭数は前走で数える**（entry_digestの各馬の先頭行。シリウスS組を前々走まで含めて5頭と数えた誤りあり）
- 数字は元データで裏付けのあるものだけ。「このメンバーで速い」など比較の言い切りは、比較したときだけ書く

## 6. 落とし穴（実際に起きたもの）

- 下書き保存の途中でタブが応答しなくなる → 前面のタブで数本ずつ。応答なしのあと再実行すると重複
- 画像のバッチ1件目にキャラシートがそのまま保存される → 単独batchで再生成（`gen`ではキャラが渡らず別人になる）
- WebFetch・Tavilyは想定オッズが取れない／競馬ラボは403 → 想定人気は投稿の日にオッズで確認
- ブラウザの `localhost` へのfetchはページ側の制限で通らない → 文章は埋め込みで渡す
- 文字列を Bash の heredoc で Python に渡すと日本語が化ける → ファイルに書いて実行する

## 5. 毎週の積み上げ手順

### レース前
1. 枠順確定後に netkeiba 出馬表キャッシュを取り直して週末データを作る（`collect_weekend_bigdata.py`。9/11に「キャッシュ使い回しで9〜11Rしか入らない」原因を特定）
2. 全券種オッズを保存（`odds_snapshot.py`・前日夜と当日朝）
3. うましる追い切りを保存（`oikiri_store.py --add`）
4. YouTube予想のシグナルを `research/*_influencer.json` に保存
5. 20因子採点（`score_v33_YYYYMMDD.py`）→ 印
6. R1で買い目（`kaime_YYYYMMDD.py`）。当日朝の実オッズで人気を再判定
7. **当日朝に買い目が確定したら** `rule_forward_ledger.py --add-week <週フォルダ>` で登録（枠順確定版の段階では登録しない＝最終の買い目で測る）

### レース後
1. `fetch_payouts.py --dates` → `weekly_forward_test.py --date`
2. `influencer_ledger.py --add-week <research> --date`（土日1回ずつ）
3. `rule_forward_ledger.py --settle` → `--report`（R1の前向き成績と、事前登録した判定基準での判定）
4. `rule_validation.py` / `policy_validation.py` を回し直し、判定基準を確認

| 🔥穴 | 3着内 3/25（12%）・平均8.0番人気。**同人気帯の平均は16%なので上乗せ価値は無い**。穴軸で組んだ買い目の合計は75,500円 → 24,780円（33%） |
| ◎ | 1着 7/27（26%）・3着内 14/27（52%）・平均1.9番人気（25/27が1〜3番人気）。**同人気帯の期待は25%/55%で、ほぼ一致＝印は人気の言い換えになっていて上乗せが測れない** |

**原因は「自分で書いた予算ルールを券種最適化が上書きしていること」**

docxに明記している予算ルールは「自信度連動（10=15,000／9=12,000／8=8,000／7=5,000、新馬・未勝利は60%）」。ところが実際の金額は券種最適化が推定期待回収率から決め直しており、**推定が高く出る穴狙いに資金が集まり、実際に当たった堅いレースには少額しか置いていなかった**。

| 買い目は一切変えず、金額だけ変えた場合 | 回収率 |
|---|---|
| 実際に公開した配分 | 35% |
| 3連複を全部やめて同レースの他券種へ回す | **57%** |
| 規定の予算ルール（自信度連動×未勝利60%）どおり | **72%** |
| 自信度10のレースだけ（買い目そのまま） | 99%（9R） |
| （参考）馬連◎-○1点だけ / 馬連BOX3(◎○▲) | 27% / 9% |

払戻があった4レース（札幌6R 12,510円・赤倉特別 24,780円・阪神6R 10,560円・阪神2R 11,340円）は**すべて規定額より少ない金額しか置いていない**。逆に15,000円・13,000円を置いた大口5本はすべて0円で、うち2本は「穴ワイド2点」だった。前日推定の期待回収率347%・231%は実オッズでは成立しない（9/12に記録済みの過大推定問題と同じ）。

⚠ n=27・的中6なので、自信度別の数字（9=0%）は偶然の可能性がある。**確度が高いのは「3連複7%」「🔥穴に上乗せ価値なし」「推定期待回収率が過大」の3つ**で、これらはバックテスト側の結論とも一致する。

**▶ 次の週末に反映する変更（2026-09-16 ユーザー承認済み・実装完了）**
1. **3連複を買わない**（実戦7%・バックテストでも最下位）
2. **🔥穴を買い目の軸にしない**（3着内12%＝人気なり。印としての表示は残す）
3. **予算は必ず自信度連動ルールで決める**。券種最適化に金額の決定権を渡さない（券種の選択だけにする）
4. **期待回収率は実オッズで検算した値だけを出す**。推定値しか無い券種は表示しない
5. 自信度9以下は投資額を落とす案は、サンプルを貯めてから（今は偶然と区別できない）
